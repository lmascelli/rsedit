NAME
    compile - run a build and jump to what it complained about

SYNOPSIS
    (compile COMMAND)
    (compilation-recompile)
    (compilation-goto)
    (compilation-next)
    (compilation-previous)
    compilation-patterns
    compilation-severity-patterns
    compilation-default-severity
    compilation-window-height

DESCRIPTION
    C-c c asks for a command, runs it, and shows what it prints in a strip
    along the bottom of the frame while you go on working. A line of the
    output that names a file and a line, such as src/main.rs:12:5, is a
    place: M-g n and M-g p go from one place to the next, from the window
    you are working in, and Return on one in the output opens it too.

    Each place is also a finding of the producer compile, with how bad
    the compiler says it is: the file it names shows it where the text
    is, in the gutter and in the status line, as the findings page
    describes, and M-g f lists it with what other tools have said.

RUNNING A BUILD
    The command runs through the shell, in the directory the editor was
    started in, with what it prints and what it complains about in one
    stream, in the order it wrote them. The first line of the output is
    the command, as in $ cargo build; the last says how it ended:

        --- exited 0 ---        it worked
        --- exited 101 ---      it failed, with that code
        --- killed ---          it was stopped

    Each run has an output buffer of its own, *Shell Output*, then *Shell
    Output*<2>, shown in the same strip. In the output:

        g               run the same command again, where it ran
        C-c C-k         stop it
        q               close the output's window

    C-c C-k, and killing the output buffer, ask the command and everything
    it started to stop, and stop them outright two seconds later.

GOING TO THE PLACES
        M-g n           open the next place, in the window you are in
        M-g p           open the one before
        <ret>           in the output, open the place on this line
        n  p            in the output, the next and previous line with one

    M-g n walks what the compiler has said so far, so it can start before
    the build ends. Return in the output opens its place in the window the
    build was started from, and M-g n goes on from there. The line is
    marked in the file, and the place in the output. A relative path is
    taken from the directory the build ran in, even after M-x cd and from
    any buffer; when the file is not there it is said to be missing,
    rather than another file of the same name being opened.

WHICH LINES NAME A PLACE
    A line names a place when one of `compilation-patterns' matches it.
    Each entry is a list (REGEXP FILE-GROUP LINE-GROUP COLUMN-GROUP), the
    groups numbered as `match-string' numbers them, and COLUMN-GROUP nil for
    a format with no column. The first entry that matches a line decides,
    and the first line of the output, the command, names no place. Out of
    the box:

        path:line:col           gcc, clang, rustc and most linters
        path:line:              make, and tools that give no column
        --> path:line:col       rustc's second line
        File "path", line N     Python's tracebacks

THE PLACES AS FINDINGS
    Each place is reported as a finding about the file it names, under
    the producer compile, as the output comes: about four times a second
    while the build runs, and once more when it ends. The finding is at
    the line and the column the compiler gave, at the start of the line
    when it gave no column, and says:

        :severity   what the line says, or else what the line before it
                    says, or else `compilation-default-severity'
        :message    the rest of the line after the word that said the
                    severity, or else the whole line
        :code       the code in brackets after the word, when there is
                    one, as rustc writes error[E0425]

    A line says a severity when one of `compilation-severity-patterns'
    matches it. Each entry is a list (REGEXP SEVERITY MESSAGE-GROUP
    CODE-GROUP): SEVERITY is error, warning, info or hint, and the groups
    are numbered as `match-string' numbers them, nil for a format that has
    no message or no code. The first entry that matches decides. Out of
    the box:

        error: ...  fatal error: ...    error
        warning: ...                    warning
        note: ...                       info
        help: ...                       hint

    with a code in brackets allowed after error and warning. gcc and clang
    write the word on the line of the place; rustc writes it on the line
    before, as in

        error[E0425]: cannot find value `x` in this scope
         --> src/main.rs:2:5

    and only the line right before a place speaks for it, when it names no
    place itself.

    A relative path is taken from the directory the build ran in, as for
    M-g n. Each build starts over: when it starts, what the build before
    said is forgotten, even when its output buffer is still open. Closing
    the output stops the reporting, and what has been reported stays until
    the next build. Only the newest build reports: one still running in
    another output buffer no longer does.

    The output, and the places M-g n walks in it, are the same as without
    the findings: they are two ways of showing what the compiler said.

EXAMPLES
    Build with cargo from a key of its own:

        (define-key nil "C-c b" '(compile "cargo build"))

    Recognise a tool that writes "ERROR in FILE at line N":

        (setq compilation-patterns
              (cons '("ERROR in ([^ ]+) at line ([0-9]+)" 1 2 nil)
                    compilation-patterns))

    A taller window for the output:

        (setq compilation-window-height 20)

    Read a tool that writes "SEVERE: message" and "MINOR: message" after
    the place:

        (setq compilation-severity-patterns
              (append '(("SEVERE: (.*)" error 1 nil)
                        ("MINOR: (.*)" warning 1 nil))
                      compilation-severity-patterns))

    Take a place no line qualifies as a warning rather than an error:

        (setq compilation-default-severity 'warning)

    Say how many errors the last build reported:

        (let ((n 0))
          (dolist (f (findings-of-producer 'compile))
            (when (eq (nth 1 (memq :severity f)) 'error)
              (setq n (+ n 1))))
          (message "%d errors" n))
