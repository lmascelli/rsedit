NAME
    compile - run a build and jump to what it complained about

SYNOPSIS
    (compile COMMAND)
    (compilation-recompile)
    (compilation-goto)
    (compilation-next)
    (compilation-previous)
    compilation-patterns
    compilation-window-height

DESCRIPTION
    C-c c asks for a command, runs it, and shows what it prints in a strip
    along the bottom of the frame while you go on working. A line of the
    output that names a file and a line, such as src/main.rs:12:5, is a
    place: M-g n and M-g p go from one place to the next, from the window
    you are working in, and Return on one in the output opens it too.

RUNNING A BUILD
    The command runs through the shell, in the directory the editor was
    started in, with what it prints and what it complains about in one
    stream, in the order it wrote them. The first line of the output is
    the command, as in $ cargo build; the last says how it ended:

        --- exited 0 ---        it worked
        --- exited 101 ---      it failed, with that code
        --- killed ---          it was stopped

    Each run has an output buffer of its own, *Shell Output*, then *Shell
    Output*<2>, shown in the same strip. In the output:

        g               run the same command again
        C-c C-k         stop it
        q               close the output's window

    C-c C-k, and killing the output buffer, ask the command and everything
    it started to stop, and stop them outright two seconds later.

GOING TO THE PLACES
        M-g n           open the next place, in the window you are in
        M-g p           open the one before
        <ret>           in the output, open the place on this line
        n  p            in the output, the next and previous line with one

    M-g n walks what the compiler has said so far, so it can start before
    the build ends. Return in the output opens its place in the window the
    build was started from, and M-g n goes on from there. The line is
    marked in the file, and the place in the output. A relative path is
    taken from the directory the editor was started in; when the build ran
    somewhere else the file is said to be missing, rather than another file
    of the same name being opened.

WHICH LINES NAME A PLACE
    A line names a place when one of `compilation-patterns' matches it.
    Each entry is a list (REGEXP FILE-GROUP LINE-GROUP COLUMN-GROUP), the
    groups numbered as `match-string' numbers them, and COLUMN-GROUP nil for
    a format with no column. The first entry that matches a line decides,
    and the first line of the output, the command, names no place. Out of
    the box:

        path:line:col           gcc, clang, rustc and most linters
        path:line:              make, and tools that give no column
        --> path:line:col       rustc's second line
        File "path", line N     Python's tracebacks

EXAMPLES
    Build with cargo from a key of its own:

        (define-key nil "C-c b" '(compile "cargo build"))

    Recognise a tool that writes "ERROR in FILE at line N":

        (setq compilation-patterns
              (cons '("ERROR in ([^ ]+) at line ([0-9]+)" 1 2 nil)
                    compilation-patterns))

    A taller window for the output:

        (setq compilation-window-height 20)

KEYS
    C-c c                   compile
    M-g n                   next-error
    M-g p                   previous-error

KEYS IN COMPILATION MODE
    <ret>                   compilation-goto
    n                       compilation-next
    p                       compilation-previous
    g                       compilation-recompile
    C-c C-k                 shell-command-kill
    q                       delete-window
