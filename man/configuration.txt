NAME
    configuration - making it yours

SYNOPSIS
    (require FEATURE &optional FILE)
    (provide FEATURE)
    (featurep FEATURE)
    (features)
    (feature-file FEATURE)
    (feature-status FEATURE)
    (eval-after-load FEATURE FUNCTION)
    (with-eval-after-load FEATURE BODY...)
    (eval-file FILE)
    (toggle-line-numbers)
    lisp-path
    display-line-numbers
    display-line-numbers-width
    mode-line-format

DESCRIPTION
    The editor reads one file when it starts: init.lisp, in its
    configuration directory. The first time there is none, and one is
    written for you, with every module listed and a comment on each. From
    then on the file is yours, and the editor never writes it again. Read
    it before you change it: it is the shortest description of what the
    editor is made of.

    init.lisp is this editor's own Lisp, which is close enough to Emacs
    Lisp to read and is not the same language. M-: evaluates one
    expression without restarting, which is how you try a line before
    keeping it.

WHERE THE FILES ARE
    The configuration directory is the first of these that applies:

        $RSEDIT_CONFIG_DIR          as given, on any system
        $XDG_CONFIG_HOME/rsedit     on Unix, when the variable is absolute
        ~/.config/rsedit            on Unix, macOS included
        %APPDATA%\rsedit            on Windows

    What the editor can make again, such as its log, goes in the cache
    directory, found the same way:

        $RSEDIT_CACHE_DIR
        $XDG_CACHE_HOME/rsedit
        ~/.cache/rsedit
        %LOCALAPPDATA%\rsedit\cache

    What is installed for the editor rather than written for it, such as
    its plugins, goes in the data directory:

        $RSEDIT_DATA_DIR
        $XDG_DATA_HOME/rsedit
        ~/.local/share/rsedit
        %LOCALAPPDATA%\rsedit\data

    A variable that is set but empty counts as not set. The configuration
    and the cache are made when they are missing, and deleting the cache
    loses nothing that matters. The `plugins' page says what goes in the
    data directory.

THE FOUR THINGS YOU WILL WRITE
    A setting:

        (setq case-fold-search nil)        ; searching minds capitals
        (setq tab-width 8)                 ; what a Tab is worth

    A key:

        (define-key nil "C-c d" 'duplicate-line)
        (define-key 'rust-mode "C-c C-c" 'comment-region)

    A command of your own:

        (defcommand insert-date () nil
          "Insert today's date."
          (insert (shell-command-to-string "date +%Y-%m-%d")))

    Something to happen at a moment:

        (add-hook 'rust-mode "post-command-hook" 'my-function)

    C-h v on a variable says what it is for and what it is set to now, and
    C-h f does the same for a function.

MODULES
    Each feature above the mechanics is a module: a file, loaded by a line
    in init.lisp.

        (require 'completion)      ; Tab shows every candidate at once
        (require 'dired)           ; a directory in a buffer

    A module is loaded once, however many times it is asked for: `require'
    loads the file only when the feature is not loaded yet. Each module
    begins by requiring the modules it needs and ends with `provide', which
    says it is loaded, so the order of the lines does not matter. Comment
    one out and the editor comes up without that feature, unless a module
    still loaded needs it and loads it anyway. The `rsedit' page lists them
    all.

    `featurep' says whether a module is loaded, `features' lists the ones
    that are, the latest first, and `feature-file' says which file one came
    from. A module whose file raised an error is not loaded, and nor are the
    modules it loaded on its way; `feature-status' says failed, and the log
    says why.

    Since init.lisp is written once, a module a later version adds does not
    reach it by itself: add its line by hand.

    The modules are installed beside the editor, in three folders of
    data/lisp: base, what the others are written with; features, one for
    each thing the editor does; and languages, one for each language it
    colours. You can read all of them. The one to read first is
    rust-mode.lisp: a whole mode in one short file.

    An init.lisp written before modules were required loads them with
    (eval-file "dired"), which still works: `eval-file' finds a bare name
    in `lisp-path' as `require' does, but loads it again every time.

SETTINGS FOR A MODULE
    A setting the module defines with `defvar' can be set before the module
    is loaded, and the module keeps it. To run something once a module is
    loaded, wherever it is loaded from:

        (with-eval-after-load 'dired
          (setq dired-sort 'type))

    It runs now if the module is loaded already. `eval-after-load' is the
    same with a function, and is what `with-eval-after-load' is written
    with; the macro needs `commands', and the function nothing.

FILES OF YOUR OWN
    `require' looks for FEATURE.lisp in each directory of `lisp-path' in
    turn, and loads the first it finds. The list starts with the folder lisp
    of the configuration directory, then the folder of each plugin, then
    the editor's own three. So a module of your own goes in
    ~/.config/rsedit/lisp, ends with its `provide', and is loaded by name:

        ;; ~/.config/rsedit/lisp/mine.lisp
        (require 'commands)
        (defcommand hello () nil "Say hello." (message "hello"))
        (provide 'mine)

        ;; init.lisp
        (require 'mine)

    A file of yours with the name of one the editor ships is loaded in its
    place, and the log says which file shadows which. `eval-file' takes a
    path, relative to the directory the editor was started in, or a bare
    name, looked for in the same list; it loads the file whether or not it
    has been loaded, which is what you want while you are writing one.

SETTINGS
    A setting is a variable the editor reads: set it in init.lisp, or with
    M-: to try it. These are the general ones; the others are described
    with the feature they belong to.

        display-line-numbers        nil, t, or 'relative
        display-line-numbers-width  the fewest digits the numbers take
        mode-line-format            what each window's status line shows

    M-x toggle-line-numbers turns the numbers on and off. They are drawn in
    the faces `line-number' and `line-number-current', and the status line
    in `mode-line' and `mode-line-inactive'; `themes' says how to change a
    face.

COLOURS
    C-c t lists the themes, and Return on one applies it. To keep a choice,
    after the line that loads the module, (require 'theme):

        (select-theme 'monochrome)

    Or set one face at a time, which is what a theme is made of:

        (set-face 'keyword "bright-magenta")

WHEN IT WILL NOT LOAD
    A module that is not found says so in the log, and the editor comes up
    without it, which is the point of them being separate. One that is
    found and fails -- an error, a syntax error, no `provide' -- stops
    init.lisp there, and the editor with it: it prints the error and exits.
    The log in memory says which module, and is lost with it. A file loaded
    with `eval-file' that has a syntax error is skipped without a word, for
    now: when a change seems to do nothing, try it with M-: first. C-h e
    shows everything the editor has said, and the `diagnostics' page says
    where else to look.

EXAMPLES
    Whether vim is loaded, and from where:

        (list (featurep 'vim) (feature-file 'vim))

    Number each line by its distance from point, which is what a count
    before a command wants:

        (setq display-line-numbers 'relative)

    A shorter status line: the buffer, then the line and the column.

        (setq mode-line-format " %b  L%l C%c ")

    A command of your own, on a key of your own:

        (defcommand insert-date () nil
          "Insert today's date."
          (insert (shell-command-to-string "date +%Y-%m-%d")))
        (define-key nil "C-c i" 'insert-date)
