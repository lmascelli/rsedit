NAME
    dired - a directory in a buffer

SYNOPSIS
    (dired DIRECTORY)
    (dired-find-file)
    (dired-find-file-other-window)
    (dired-up-directory)
    (dired-refresh)
    (dired-mark)
    (dired-flag-file-deletion)
    (dired-unmark)
    (dired-unmark-backward)
    (dired-unmark-all-marks)
    (dired-toggle-marks)
    (dired-do-delete)
    (dired-do-flagged-delete)
    (dired-do-rename)
    (dired-do-copy)
    (dired-do-shell-command)
    (dired-delete-file)
    (dired-rename-file)
    (dired-find-recursive)

    dired-window-width
    dired-buffer-name
    dired-marker-char
    dired-del-marker
    find-file-recursive-ignore

    find-file-recursive-limit

DESCRIPTION
    C-x d asks for a directory and lists it in a buffer, one entry per
    line, where keys open, delete, rename, copy and run commands on files:
    the ones you have marked, or the one the cursor is on. C-x C-f on a
    directory does the same. C-x C-r finds a file by name anywhere
    under the directory the editor was started in.

THE LISTING
        /home/me/project/:
          ..
          Cargo.toml
          src/

    The directory on the first line, then .. and one entry per line, a /
    after each directory. `dired-sort' orders the entries: name for one
    alphabetical run, type for the directories first. The listing is
    read-only, and every listing is shown in the same buffer, *dired*:
    going into a directory replaces the one you were in. The listing has
    the directory it lists as its own: a relative name typed there, and a
    shell command run from it, are read in that directory.

MOVING AND OPENING
        <ret>           open what the cursor is on
        o               open it in a window beside the listing
        ^               go up to the parent directory
        g               read the directory again
        n  p            down and up a line
        q               close the listing

    Return opens a file in this window, and a directory as the listing; ..
    goes up. o opens a file in a window beside the listing and leaves the
    listing `dired-window-width' columns wide. Pressing o again opens the
    next file in that same window, so walking a directory leaves two
    windows, not ten. Other keys keep their meaning: C-n, C-x o and M-x
    work as anywhere else.

MARKING
        m               mark the file, for the commands below
        d               flag it for deletion by x
        u               take its mark off
        <backspace>     take the mark off the line above
        U               take every mark off
        t               mark the unmarked files, unmark the marked

    A mark is the first column of an entry: * for marked, D for flagged
    for deletion, as in Emacs:

        /home/me/project/:
          ..
        * Cargo.toml
        D old.log
          src/

    m, d and u go on to the next line, so a row of files is marked by
    pressing the key down it. t leaves the flagged files flagged. The marks
    stay when the listing is read again, and go when another directory is
    listed. .. cannot be marked.

CHANGING FILES
        D               delete the marked files, or this one
        x               delete the files flagged with d
        R               rename this file, or move the marked ones
        C               copy this file, or the marked ones
        !               run a shell command on them

    Every one of them acts on the files marked with *, or, when there are
    none, on the one the cursor is on; x acts on the files flagged with D.

    D and x ask once, before anything goes, with `yes-or-no': type yes and
    Return, or with `use-short-answers' set press y. The question says how
    many files, and which directories go with everything in them.

    R asks for a new name for one file. A plain name renames it in the
    same directory; a name with a directory in it moves it there, taken
    from the directory being listed unless it is absolute, and an existing
    directory moves it into it, with its name. With files marked, R asks
    for a directory and moves them all into it. C does the same with a
    copy, and copies a directory with everything under it. Neither ever
    replaces a file that is there already: that one is left, and the
    message says how many could not be moved or copied.

    ! asks for a shell command and runs it in the directory being listed,
    with the files' names, quoted for the shell: where a * stands alone in
    the command, or after it otherwise. What it prints is shown as by M-!.

        ! wc -l                 wc -l 'a.txt' 'b.txt'
        ! tar cf out.tar *      tar cf out.tar 'a.txt' 'b.txt'

    All of them read the directory again afterwards, and none touches .. .

FINDING A FILE ANYWHERE
    C-x C-r asks for a file anywhere under the working directory,
    completing on any part of its path. It does not go into the
    directories named in `find-file-recursive-ignore', such as .git and
    target, and leaves out what the .gitignore files of the tree say, in
    their directory and under it: `find-file-recursive-ignore-files' names
    the files it reads. It stops at `find-file-recursive-limit' files and
    says so.

    The files come from an index of the tree, which the files page
    describes under AN INDEX OF A TREE. The question opens at once, even
    on a large tree: while the tree is still being walked the echo area
    says how many files are known so far, and each Tab completes on the
    files known by then. The index is kept, so the next C-x C-r in the
    same directory is instant; it is walked again in the background when
    it is older than `file-index-max-age' seconds, and a file made since
    then is offered once that walk has ended.

LIMITS
    Of the .gitignore syntax, everything but [:alpha:] and the other
    named classes is understood; a line with one is skipped, so the search
    may offer a file git would hide, but never hides one git would show.
    The .gitignore files above the working directory, .git/info/exclude
    and git's own global excludes file are not read, and upper and lower
    case always differ.

EXAMPLES
    Directories first, in every listing:

        (setq dired-sort 'type)

    A wider listing beside the files o opens:

        (setq dired-window-width 60)

    Stop sooner, and leave out one more directory:

        (setq find-file-recursive-limit 20000)
        (setq find-file-recursive-ignore
              (cons "third_party" find-file-recursive-ignore))

    Read the .ignore files too, and not only .gitignore:

        (setq find-file-recursive-ignore-files '(".gitignore" ".ignore"))

    List a directory from Lisp:

        (dired "~/projects")

    Delete in dired with y or n rather than a typed yes:

        (setq use-short-answers t)
