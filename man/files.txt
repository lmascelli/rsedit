DESCRIPTION
    Opening a file reads it into a buffer. From then on you are editing the
    buffer, and the file on disk stays as it was until you save.

        C-x C-f         open a file, or make one
        C-x C-s         save this buffer
        C-x C-w         save it under another name, and edit that
        C-x C-c         quit, asking about anything unsaved

OPENING
    C-x C-f asks for a path, and Tab completes it; after a directory, Tab
    lists what is in it. The buffer is named after the file. Two files with
    the same name in different directories get different buffers, the
    second called name<2>, and opening a file that is open already goes back
    to its buffer.

    A file opened before opens where point was when it was left, and M-g r
    opens one of the files opened before, chosen from a list: the `session'
    page says how both are remembered from one run to the next.

    A path that does not exist gives an empty buffer that remembers where it
    belongs, and the echo area says "(New file)". Nothing is written until
    you save, so killing the buffer instead leaves no trace.

    A directory is shown by dired: see the `dired' page. More exactly, it is
    handed to the function in `*open-directory-callback*', which dired sets;
    without one, C-x C-f says the path is a directory.

SAVING
    C-x C-s writes the buffer to its file. C-x C-w writes it to another
    path and visits that from then on: the buffer takes the new file's
    name, its mode is chosen again from that name, and the old file is left
    as it was. C-x C-w refuses a path another buffer is already visiting.

    A save is whole or not at all: the new text is written beside the file,
    with its permissions, and only then takes its place, so a save that
    stops halfway -- a full disk, the power gone -- leaves the file as it
    was. A symbolic link stays a link, and a file with other names, or
    owned by somebody else, is written in place so that it stays so.

    In a buffer with `whitespace-cleanup-mode' on, a save first takes away
    the spaces at the ends of lines: see the `editing' page.

BEFORE SAVING
    Every manual save runs `before-save-hook' before copying the text to
    write: C-x C-s, C-x C-w, the saves offered when leaving, and their
    synchronous Lisp functions and asynchronous counterparts. Hooks run
    on the command thread, with the target buffer current, and changes
    they make are included in the save. Local auto-save copies do not run
    this hook or clean the text.

    Register named functions as for other hooks: a major mode's first,
    then the active minor modes in activation order, then global hooks.
    The `modes' page describes add-hook and remove-hook. For example:

        (defun check-note-before-save ()
          (if (= (point-min) (point-max))
              (error "The note is empty")))
        (add-hook 'fundamental-mode "before-save-hook"
                  'check-note-before-save)

    The first hook error stops the remaining hooks and aborts the save,
    with an echo-area message and a log entry. Edits already made by the
    hooks remain in the buffer and can be undone. Removing, renaming or
    changing the visited file of the target buffer also aborts the save.
    A recursive save of the same buffer is refused. Each callback starts
    in the target buffer; afterwards the caller's current buffer is
    restored if it still exists. User hooks that do slow work can delay
    the command thread, including for an asynchronous save.

    `whitespace-cleanup-mode' registers its cleanup on this hook, scoped
    to the buffers where the minor mode is on.

SAVING MORE THAN ONE BUFFER

    M-x save-some-buffers offers each buffer with unsaved changes that is
    visiting a file:

        y               save this one
        n               leave it
        !               save this one and every one left
        q               stop asking

    The question takes only those keys: anything else, C-g included, does
    nothing while it is up.

WHEN THE FILE CHANGES UNDER YOU
    Something else writing a file you have open -- a build, a branch
    switch, another editor -- is noticed within a few seconds. A buffer
    with no unsaved changes is read again on its own, and the log says so.
    A buffer with unsaved changes is left alone and marked: the next C-x C-s
    asks before writing over what is on disk now.

    M-x revert-buffer reads the file again on purpose, asking first when
    there is something unsaved to lose. The undo history and the mark go
    with the old text.

    `watch-files' turns the watching off, and `watch-file-interval' is how
    many seconds pass between looks, 3 to begin with. Checks run on separate
    workers, at most two at once, rotating through the buffers. An access
    error is shown as File unavailable; the buffer is preserved. Checks
    resume when the mount answers, and saving always checks the current
    disk stamp even with watching disabled.

AUTO SAVING
    Every half minute, each file buffer with changes not yet copied is
        copied into the cache autosave directory, four at most each time and
    the rest
    at the next. The copy is for the editor stopping without being asked
    -- a crash, a lost terminal -- and saving the buffer deletes it.
    Opening a file that has a copy says so.

    M-x recover-file puts the copy in the buffer, after asking. It comes in
    unsaved: C-x C-s keeps it, and M-x revert-buffer goes back to the file.

    `auto-save' turns it off, and `auto-save-interval' is how many seconds
    pass between one round of copies and the next.
    `auto-save-directory' defaults to the cache returned by the platform
    directory utility, with autosave appended; RSEDIT_CACHE_DIR and the
    platform cache conventions apply. Choose a local path if your home or
        cache was redirected to a network mount. Every copy goes there, the
    file's
    path flattened into its name, so that two files called main.rs keep a
    copy each: /home/me/notes.txt has #!home!me!notes.txt#, and a !, a %
    or a : in a path is written %21, %25 or %3A, so that no two paths share
    a name. A ~ in it is the home directory, and the directory is made
    when the first copy is written. A copy that cannot be written is tried
    again at the next round; the echo area, log and mode line report errors.
    An unavailable cache never silently redirects recovery writes to the
    remote directory. Setting auto-save-directory to nil explicitly opts
    into the previous beside-file policy.

SLOW OR DISCONNECTED MOUNTS
    Interactive open, save, write-file, revert, save offers and quit use
    asynchronous counterparts. Ordinary Lisp calls remain synchronous:
    (find-file PATH) still returns only after reading, so existing scripts
    can immediately operate on that buffer. A command's interactive-function
    property selects its asynchronous counterpart for call-interactively.

    find-file-async accepts AFTER, called with the buffer name, or nil on
    failure or for a directory. save-buffer-async and write-file-async call
        AFTER with t when the snapshot was written, nil on I/O failure. A
    refused
    request, failing before-save hook or cancelled conflict does not call
    AFTER. They return t for an accepted request and nil if refused. Edits
    made during a save remain
    modified;
    edits made during a revert prevent its result from replacing the buffer.

    file-io-timeout defaults to 10 seconds; set it to another number (at
    least 0.1), or nil to disable warnings. A warning is not cancellation:
    the operating system may still finish a write later. A pending write
    retains its file reservation. There are at most four saves, two opens
    or reverts, two watcher checks and one recovery job in progress. Busy
    requests are refused; no growing queue of blocked threads is created.
    Save As to a different local destination remains available while a
    remote write is pending, subject to the save limit. A late result for
    the old path cannot repoint the buffer back to it.
    The default mode line includes %i for I/O and recovery status.

    A recovery copy precedes each manual write. Recovery work is isolated
    from remote I/O, and a copy is removed after a verified successful save
    only when no newer unsaved edits depend on it. Cache errors are visible;
    the requested manual save is still attempted. Closing a buffer or normal
    quitting waits for pending writes; quit-without-saving forces exit and
    cannot promise that a write already in the kernel will be cancelled.

    A save compares modification time and size before preparing the write
    and immediately before replacement, and asks on a conflict. Confirmation
    applies to the buffer version and disk stamp shown then; a later change
    needs another confirmation. This reduces conflicts; it is not a server
    lock, an atomic compare-and-swap, or a content-hash comparison. Network
    filesystem caching and another writer can still race these checks.
    In-place fallbacks for hard links or ownership cannot guarantee atomic
    replacement. A return from write does not guarantee server durability.

    Directory browsing, filename completion, filesystem Lisp primitives,
    user hooks and synchronous script calls can still block on their own
    filesystem accesses. The timeout reports asynchronous operations only.
    For an unresponsive mount, keep working in memory or save to a different
    local file; do not force quit while a remote write is pending unless
    you accept its uncertain outcome.

I O AND RECOVERY STATUS
    %i in mode-line-format now distinguishes File missing, Access denied,
    Network unavailable, I/O timed out, Read-only filesystem, No space left,
    I/O busy, Invalid path, configuration errors and Outcome uncertain.
    Unknown errors remain I/O error. These are filesystem observations,
    not a separate network connectivity test. A slow operation stays pending;
    a warning alone does not declare the connection lost or cancel the call.
    Native error kinds, OS codes and messages are retained. Known stale NFS
    handles and Windows unavailable-share errors count as network failures.

    M-x file-io-status shows the full recorded error and recovery report;
    M-x auto-save-status shows the last completed recovery attempt, its UTC
    date and time, destination, buffer version and last successful attempt.
    Both commands return that text and perform no filesystem operations.
    %i shows a compact summary, for example [AS ok 10:32:07Z] or
    [AS denied 10:33:12Z]. Z means UTC. [AS never] means no completed attempt
    has been recorded in this buffer. History lasts for the buffer's life,
    and includes the recovery copies made before manual saves.

    Completion time is recorded when the local write returns, independently
    of a delayed UI callback or a pending remote save. A failed attempt keeps
    the last-success date. A skipped older snapshot does not invent another
    write or replace its timestamp. Removing a copy after a successful save
    preserves this history, with the removal stated in the detailed report.
    The report describes past attempts; it does not promise that newer edits
    are already copied, or that a recovery file still exists on disk.

LEAVING
    C-x C-c asks about each buffer with unsaved changes, as
    save-some-buffers does. If any are still unsaved after that, quitting
    has to be confirmed by typing yes. Buffers with no file behind them,
    such as *scratch* and the listings, are never asked about: there is
    nowhere to save them. M-x quit-without-saving asks nothing.

QUESTIONS
    The editor asks in two ways. A question answered with one key, y or n,
    takes only its keys. A question about something that cannot be undone
    wants yes or no typed in full and Return; Escape closes it, which
    counts as no. `y-or-n' and `yes-or-no' ask the same questions for a
    command of your own, and call a function with the answer.

    With `use-short-answers' set, as in Emacs, the questions that want yes
    or no typed are answered with one key as well: y or n, and C-g or
    Escape for no. It is nil unless you set it.

CODINGS
    A file is read in UTF-8 when it is UTF-8, and in windows-1252 when it
    is not: the coding of older files written on Windows in a western
    language, where è or € is a single byte. Any file opens this way, and
    the echo area says "Not UTF-8: read as windows-1252". The buffer keeps
    the coding, and saving writes the file in it, so a file opened and
    saved unchanged comes back exactly as it was. M-s g searches such a
    file in the same coding.

    A character the coding does not have, such as ā in windows-1252, cannot
    be saved in it: the save is refused, saying which character, and the
    file is left alone. M-x set-buffer-file-coding writes the file in
    another coding from the next save on, utf-8 for any character; M-x
    buffer-file-coding says which one the buffer has. A UTF-8 file that
    begins with the signature some Windows programs write is read without
    it, as utf-8-with-signature, and saved with it again.

FILES FROM LISP
    `read-file-to-string' reads a file without making a buffer for it.
    `list-dir' lists a directory, a / after each subdirectory, by name or
    with the directories first. `directory-files-recursive' lists every
    file under a directory, skipping the directory names and the file
    endings it is given, and stops at a limit; its answer says whether it
    stopped.

    `delete-file' refuses a directory that is not empty unless it is told
    otherwise, and deletes a symbolic link rather than what it points to.
    `rename-file' refuses to replace a file that is there already, and
    does not cross from one filesystem to another. `copy-file' refuses to
    replace one too, copies a directory, with everything under it, only
    when told it may, never into itself, and copies a symbolic link inside
    one as a link where the platform has them.

    A leading ~ is the home directory to all of these except
    directory-files-recursive, which takes its directory as it is given.

THE WORKING DIRECTORY
    A relative path, typed at C-x C-f or given to a function, is read in
    the working directory: the directory the editor was started in, until
    M-x cd moves it. Shell commands and builds start in it, and M-x grep
    searches under it. M-x pwd says which it is, and `working-directory'
    returns it.

    A buffer can have a directory of its own, which relative paths and
    shell commands use there instead: a dired listing has the directory it
    lists, and the output of a command the directory it ran in.
    `set-buffer-directory' gives the current buffer one, and nil takes it
    away.

    Moving it changes nothing that has started already: a command still
    running stays where it began, and the output of a command or a build
    keeps the directory it ran in, so g runs a build again there.

PATHS
    `expand-file-name' makes a path absolute: ~ becomes the home
    directory, a relative path is taken from DIRECTORY or from the
    working directory, and . and .. are resolved by name, without looking
    at the disk. The other four take a path apart or put it together:

        (file-name-directory "/a/b/c")          "/a/b/"
        (file-name-nondirectory "/a/b/c")       "c"
        (file-name-as-directory "/a/b")         "/a/b/"
        (directory-file-name "/a/b/")           "/a/b"

    `path-separator' is what goes between the paths of a variable such as
    PATH: ":" on Unix, ";" on Windows. `getenv' and `setenv' read and set
    the environment every program the editor starts sees; the editor's own
    process keeps the one it started with, so a ~ in a path is still the
    home it had.
    `data-directory' is where the editor's own modules, pages and themes
    are installed.

EXAMPLES
    Answer every yes-or-no question with y or n:

        (setq use-short-answers t)

    Keep the auto-save copies out of your project directories:

        (setq auto-save-directory "~/.cache/rsedit")

    Look for changes on disk every second, or not at all:

        (setq watch-file-interval 1)
        (setq watch-files nil)

    Open a file from Lisp, in the home directory:

        (find-file (expand-file-name "~/notes.txt"))

    Every file under the current directory but those in target and .git,
    and the lock files:

        (directory-files-recursive "." 1000 '("target" ".git") '(".lock"))

    Ask before doing something that cannot be undone:

        (yes-or-no "Empty the log file?"
                   (lambda () (message "emptied"))
                   (lambda () (message "left alone")))

    The parent of a directory:

        (file-name-directory (directory-file-name "/a/b/"))
