NAME
    findings - what tools have said about files, kept, drawn and listed

SYNOPSIS
    (finding-set PRODUCER FILE ENTRIES &optional UNIT)
    (finding-clear PRODUCER &optional FILE)
    (findings-for-file FILE)
    (findings-of-producer PRODUCER)
    (findings-under DIRECTORY)
    (findings-mode &optional ARG)
    (global-findings-mode &optional ARG)
    (findings-list)
    (findings-list-under DIRECTORY)
    (findings-list-goto)
    (findings-list-show)
    (findings-list-refresh)
    findings-window-height
    findings-list-buffer-name

DESCRIPTION
    A build, a linter, a spelling checker: each is a producer of
    findings, things it has to say about a span of a file -- an error on
    line 12, a warning from column 4 to column 9. The editor keeps them
    all in one place, by file and by producer, so that one piece of Lisp
    can report them and any other can ask for them: everything said about
    this file, everything this producer said, everything said about the
    files under that directory. The builds C-c c runs are one of them,
    the producer called compile (see compile).

    Where `findings-mode' is on, the findings about the file a buffer
    visits are drawn: the text they are about is underlined in the colour
    of their severity, the line each starts on has a sign in the gutter,
    the status line counts them, and the echo area says the one the
    cursor is on. M-g f lists them, and M-g n walks the list. The mode is
    on in every buffer unless turned off.

A FINDING
    Each finding is a property list:

        :start      (LINE . COLUMN) where the span starts
        :end        (LINE . COLUMN) where it ends; :start when not given
        :severity   error, warning, info or hint
        :message    a string
        :code       a string, a symbol or a number, optional: the
                    producer's name for the kind of finding, which
                    comes back as a string

    A property is read with memq and nth: (nth 1 (memq :message f)).

    Lines count from 1 and columns from 0, as the producer counted them.
    The columns count characters, unless `finding-set' is given a UNIT:
    utf-16 for UTF-16 code units, or utf-8 for bytes. UTF-16 differs from
    characters only after a character outside the basic plane, such as
    an emoji, two units; UTF-8 after any that is not ASCII: an é is two
    bytes, an emoji four. The editor keeps the columns as they came and
    reads them in their unit where the text of the file is: in an open
    file, and in one opened later.

    A producer is named by a symbol or a string: 'my-lint and "my-lint"
    are the same producer. A file is named as C-x C-f names one: a
    relative name is read in the current directory, and is kept as an
    absolute one.

REPLACING
    A producer never adds or removes one finding: `finding-set' replaces
    everything it said about a file with a new list, in one go, and
    returns how many findings there are now. What other producers said
    about the file, and what this one said about other files, stays. So
    a producer that has looked at a file again reports all it found, and
    what it no longer finds goes without being asked.

    An empty list forgets what the producer said about the file.
    `finding-clear' does the same, or, without a file, forgets every file
    of the producer: what a build does before it starts again.

    A list with an entry that is not a finding -- no :start, no :message,
    a severity that is not one of the four, a negative line -- is refused
    whole, with wrong-type-argument, and what was there before stays.

ASKING
    `findings-for-file' returns the findings about one file, producer by
    producer, each in the order it was given. `findings-of-producer'
    returns one producer's, file by file, and `findings-under' those about
    the files in a directory and in every directory below it, file by
    file. A directory is a whole name: /src/app holds /src/app/main.c,
    not /src/application.c.

    Each finding comes back as it went in, with four more properties:
    :file, the absolute name of the file; :producer, as a symbol; :unit,
    what its columns count, char, utf-16 or utf-8; and :stale, described
    below. `line-column-to-position' takes the :unit as it is.

IN AN OPEN FILE
    When the file is open, in a buffer, each finding follows its text: a
    line added above it moves it down, as it moves the places of a list
    of results (`compile'). This holds whether the file was opened before
    the findings came or after: opening it places them. The places asked
    for are then where the text is now, not where the producer said, and
    their columns count characters: :unit is char.

    Once the buffer's text has changed since the producer spoke, every
    finding of that producer about the file has :stale t: it was right
    about a text that is no longer the one you have. It stays so until
    the producer replaces its findings, which makes them fresh again.

    Closing the buffer gives the findings back the places the producer
    said, and a finding stale when it closed stays stale.

ON THE SCREEN
    Each finding is drawn over its span in a face of its severity:
    finding-error, finding-warning, finding-info or finding-hint, which
    the editor ships underlined, the first three in red, yellow and cyan.
    A finding with no span, whose :end is its :start, takes the character
    at its start, or the cell after the line when it is at the line's end.
    Where two findings cover the same text the more severe is drawn over
    the other. The search's matches, the overlays and the region are drawn
    over them all.

    While the buffer's file has findings, the gutter has two columns more,
    in front of the line numbers if they are on: a sign on the line each
    finding starts on -- E, W, I or H, in finding-error-sign,
    finding-warning-sign, finding-info-sign or finding-hint-sign -- and the
    sign of the most severe when several start there. The columns go when
    the last finding does, and a window too narrow to spare them has none.

    %! in `mode-line-format' is the count of the findings, by severity,
    each after a space: " E2 W1", and nothing when there are none. The
    status line as the editor comes has it after the mode's state.

    With the cursor on a finding, from its first character to the one
    before its end, and the echo area having nothing else to say, the
    echo area says it: its severity, the first line of its message, its
    code and its producer, as

        error: undefined name [E1] (my-lint)

    When the cursor is on several, the most severe is said, and how many
    more there are. A message of the editor's own takes its place, and the
    finding is said again once that message has gone.

    All of it is worked out each time the screen is drawn, from the
    findings as they are then: a producer that replaces its findings
    changes the screen with no further step.

THE LIST
    M-g f lists the findings about the file of the current buffer in a
    buffer of its own, *Findings*, one to a line:

        main.c:12:5: error: undefined name [E1] (my-lint)

    the file named from its directory, the line from 1 and the column
    from 1, as a compiler writes them, then what the echo area says, and
    (stale) for a finding whose file has changed since its producer spoke.
    M-x findings-list-under lists those about the files in a directory and
    below it, named from that directory. The findings come in the order
    `findings-for-file' and `findings-under' give them.

    The list is the one M-g n and M-g p walk (see searching), and Return
    goes to the finding on the cursor's line. Before each step of M-g n
    the list is asked of the findings again, so that it says what the
    producers say now; g does the same at once. Its entries are counted by
    the line they are on, one to a line after the first.

LIMITS
    A place past the end of its line stops at the end of the line, and a
    line past the end of the file at the file's end.

    The list M-g f makes reads every column as characters. In a file not
    open whose findings came in utf-16 or utf-8, a step to one lands a
    little past it when its line has, before it, a character that takes
    more than one unit.

    A buffer that comes to visit a file by being saved under its name,
    with C-x C-w, does not take that file's findings: they are placed the
    next time the file is opened.

    A finding is kept for as long as the editor runs, and not in the
    session: what a producer said is the producer's to say again.

    Only the findings about the file a buffer visits are drawn, and only
    in its windows: a buffer that visits no file has none. A float, such
    as a strip of choices, draws the spans but has no gutter, and so no
    signs. A list rebuilt by M-g n keeps its place by number: when the
    findings before it have changed, the next step may skip one or show
    one again.

EXAMPLES
    A checker of your own that reports two findings about a file, one an
    error over a span and one a hint at a point.

        (finding-set 'my-lint "~/src/app/main.c"
          '((:start (12 . 4) :end (12 . 9) :severity error
             :message "undefined name" :code "E1")
            (:start (30 . 0) :severity hint :message "line is long")))

    A producer that counts columns in UTF-16: here the span is the word
    after an emoji, units 3 to 8.

        (finding-set 'my-checker "~/src/app/main.c"
          '((:start (5 . 3) :end (5 . 8) :severity warning
             :message "unused"))
          'utf-16)

    The errors about the file in the current buffer, as messages.

        (dolist (f (findings-for-file (buffer-file-name)))
          (when (eq (nth 1 (memq :severity f)) 'error)
            (message "%s" (nth 1 (memq :message f)))))

    How many findings there are under a directory, all producers counted.

        (length (findings-under "~/src/app"))

    A build that starts over forgets everything it said last time.

        (finding-clear 'my-build)

    The findings drawn, but not in the status line: a format without %!.

        (setq mode-line-format " %* %b   %m%n  L%l C%c ")

    No findings drawn in the buffers of one mode.

        (defun my-quiet-setup () (minor-mode-off 'findings-mode))
        (add-hook 'python-mode "after-change-major-mode-hook"
                  'my-quiet-setup)

    Errors in a softer colour, as a theme would set them.

        (set-face 'finding-error "#cc6666" nil '("underline"))
