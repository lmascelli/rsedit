NAME
    indentation - what Tab and Return do

DESCRIPTION
    Tab puts the line where its mode says it belongs, and Return starts the
    next line there too. The editor has no opinion of its own about how a
    language is indented: a mode gives its rule, and a buffer whose mode
    has none goes by the line above.

    Indentation is written with spaces, never with tab characters.

TAB ON A LINE
    Tab indents the line point is on, wherever point is on it, as in
    Emacs. Point stays on the character it was on, or goes to the start of
    the text when it was in the indentation. A line already where it
    belongs is left as it is, however many times Tab is pressed.
    `tab-always-indent' decides when to indent and when to insert spaces:

        t               always indent; the default
        complete        indent, then try completion if nothing changed
        nil             indent in leading whitespace; after text, insert
                        spaces up to the next tab stop

    A tab stop is every multiple of `indent-width', so text after a Tab
    lines up with text after another, wherever each began.

    A mode can offer alternative indentation levels. The first Tab uses its
    suggested column; consecutive Tabs choose the next smaller alternative,
    wrapping from the minimum to the maximum. For example, Python can cycle
    8, 4, 0, 8 after an ordinary statement inside nested blocks. Another
    command ends the cycle. A Tab in leading whitespace with alternatives
    never adds spaces just because the line was already correctly indented.

    Without alternatives, consecutive Tabs with nil insert spaces instead
    of repeatedly undoing the preceding Tab's indentation. With complete,
    completion is still available after text when indentation and point did
    not change. M-x indent-line only applies the suggested column; it does
    not cycle or insert extra spaces.

    M-m goes to the first character on the line that is not a space.

    In a mode with no rule of its own, such as fundamental-mode, there is
    nothing to put the line where it belongs, and Tab works as Emacs'
    indent-relative. In the indentation it brings the line up to the
    indentation of the line above, or, when it is there or further already,
    on to the next tab stop: it never takes indentation away. After the
    text it inserts spaces up to the next tab stop, or with complete tries
    completion.

TAB ON A REGION
    With a region, Tab works on every line the region touches. A region
    that ends at the very start of a line leaves that line out, which is
    what selecting whole lines from the left margin wants. The region stays
    selected afterwards, so pressing Tab again works on the same lines.

    What Tab does to them is `indent-region-style':

        reindent        put each line where the mode's rule says
        shift           move the block right by one Tab, keeping its shape
        auto            reindent when the mode has a rule, shift when not

    auto is the default because, with no rule, putting each line where the
    one above is would flatten a nested block to one column. A mode can
    choose for itself: (put 'MODE 'indent-region-style 'shift).

SHIFTING
    S-<tab> moves the region, or the line, left by one Tab, and M-x
    indent-rigidly-right moves it right. The lines keep their shape, and
    in a region a line already at the margin stays there while the others
    go on moving. Blank lines in a region are left alone.

RETURN
    Return runs `newline', which only inserts a newline. The indenting is
    done by the minor mode `electric-indent-mode', on in every buffer, as
    in Emacs: after the newline it indents the line Return opened as Tab
    would. The line Return ends is tidied first: the spaces at its end go,
    and it is indented again where the mode has a rule, since a word typed
    on it may have changed where it belongs. Return on an indented blank
    line leaves that line empty, and the new line keeps the indentation
    chosen there, including a level selected by Tab or Shift-Tab. It never
    cycles alternatives.

    A mode can ask for the line Return ends to be left where it is, as
    python-mode does, since there a dedent is a choice:

        (put 'MODE 'electric-indent-inhibit t)

    A mode can also name characters that indent their line when typed
    first on it, such as the brace that closes a block in C and Rust:

        (put 'MODE 'electric-indent-chars '("{" "}"))

    M-x electric-indent-mode turns it off in the buffer you are in, and on
    again; Return is then a plain newline, and M-x newline-and-indent still
    indents. `newline' called from Lisp never indents, and neither does
    `insert-newline', bound to a key or not.

HOW WIDE A TAB IS
    `tab-width' is the width of one Tab everywhere, 4 unless it is set: how
    far Tab indents, and how far a tab character in the text reaches on
    the screen, to the next multiple of it. A mode can have its own:
    (put 'MODE 'tab-width N). risp-mode, toml-mode and cmake-mode use 2;
    python-mode, bash-mode, c-mode and cpp-mode use 4. Drawn, a tab is
    between 1 and 64 columns wide.
    `indent-width' is the width in force in the current buffer.

WRITING A RULE
    A rule is a function of no arguments. It is called with point on the
    line to indent and returns the column that line should start at; it
    may move point, but it does not change the buffer. The editor does the
    rest: it puts the line at the column, as one undo step, and puts point
    back.

        (put 'MODE 'indent-function 'FUNCTION)

    A mode can additionally supply a function of no arguments returning a
    proper list of alternative non-negative integer columns:

        (put 'MODE 'indent-levels-function 'LEVELS-FUNCTION)

    The order does not matter. Rust sorts and deduplicates the columns and
    includes the suggested column. Return nil to disable cycling in a
    context, such as a string or a bracket continuation. The function must
    compute the alternatives independently of a dedent written on the current
    line, so choosing column zero does not lose the way back inside a block.
    It may move point while reading, but must not edit the buffer. Point is
    restored even when either rule signals an error. The alternative rule is
    used only by interactive Tab, never by Return or indent-region.

    These commands and cycling are native Rust machinery; language-specific
    rules remain Lisp, and existing modes need not supply alternatives.

    The functions a rule is written with are `current-indentation' and
    `previous-indentation', which read the indentation of a line, and
    `current-column'; `syntax-ppss' says how deep in brackets a position
    is. `indent-line-to' is what moves a line, for a command that indents
    by itself.

LANGUAGE RULES
    Python indents after a compound header's colon, aligns elif, else,
    except and finally with a preceding header, and puts case one level
    inside match. Arguments align with the first argument on the opener's
    line, or one level inside an otherwise empty delimiter. Closing
    delimiters return to the opener's line's indentation. Explicit
    backslash continuations use one extra level, without accumulating it.
    Multiline string contents keep their indentation.

    A written Python dedent is meaningful syntax and is preserved. A blank
    line after return, raise, break, continue or pass dedents one level.
    After an ordinary statement, consecutive Tabs can choose outer levels
    without requiring a special statement at the end of a block. Headers and
    clauses keep their suggested column; strings and bracket continuations
    do not cycle.
    Reindentation cannot recover missing block boundaries in Python; use
    rigid shifting when changing the nesting of an existing block.

    TOML keys and table headers begin at column zero. Array and inline-table
    continuations align with the first value or one level inside the opening
    line. A closing delimiter returns to that line's indentation. Multiline
    string contents, including their closing lines, keep their whitespace.

    Bash follows if/then/elif/else/fi, for/while/until/select/do/done,
    case/esac, function braces and subshells. A case pattern is one level
    inside case, and its commands one level further. Pipe, &&, || and
    backslash continuations add one level. Quoted text and comments do not
    create control-flow blocks. Literal-word heredocs, including quoted
    markers, multiple pending heredocs and <<-, keep their contents and
    terminators untouched.

    CMake indents one level inside if, foreach, while, function, macro and
    block, and aligns elseif, else and the end commands with the command
    that opened the block, in any case. Arguments that go on to more lines
    align with the first argument on the command's line, or go one level
    in when the ( ends it; a ) alone returns to the command's column. The
    lines inside a quoted argument, a bracket argument or a bracket
    comment keep their indentation.

    C/C++ indent within braces, align continued argument lists, recognize
    unbraced control statements, and indent case bodies one level beyond
    their labels. Access labels align with their class's opening line;
    preprocessor directives begin at column zero. Character literals,
    registered raw strings and comments do not count as brackets. A line
    the one above left unfinished, ending in an operator or a comma, goes
    one level further; but in a list of values -- an enum, an initializer
    after =, an element of one, a C++ return {, or C++'s initializer after
    a name or a type, as in Foo f{ or std::vector<int>{ -- a comma ends an
    item, and the next lines up with it. The heads of classes, namespaces
    and functions, which end in a name too, still open blocks, and so do a
    lambda's, with or without parameters ([] -> int {), and a requires
    clause or expression.

    Rust indents one level inside braces, from the statement that opened
    the block however many lines it took, so struct fields and match arms
    are one level in and a closing brace goes back to the statement. A
    line that goes on with the statement above -- a method chain, a line
    starting with && or ||, or one after a line ending in an operator, = or
    => -- is one level further. Inside parentheses and brackets arguments
    line up as in C. A comma ends no line in a block: the next field or
    arm stays where the first is.

THE LISP RULE
    `lisp-indent-line' is the rule for this editor's own Lisp, and
    risp-mode uses it. It reads only the brackets, so it works for any mode
    whose syntax pairs parentheses:

        (foo bar        a call lines its arguments up under the first,
             baz)       when the first is on the line of the call, and
                        otherwise puts them one column in
        (defun f ()     a form with a body indents it by two columns
          body)
        ((a b)          a list that starts with a list, one column in
         c)

    The forms with a body are the names with a lisp-indent property:
    defun, let, when, while, dolist and the others like them. A string
    keeps the indentation it has.

LIMITS
    These are indentation rules for editing, not complete formatters.
    Malformed or ambiguous code, complex C/C++ macros and conditional
    compilation can need manual indentation. Bash arithmetic commands,
    complex substitutions, escaped or computed heredoc delimiters are not
    fully parsed. TOML inline tables can be indented while editing even
    when a TOML version requires them to be on one line. CMake reads only
    the command a line begins with: in if(A) set(x 1), on one line, the
    next line goes in for the if, and two end commands on one line take
    back one level.

    A tab character in the text counts as one column, wherever the editor
    counts columns: in `current-column', in indentation, in rectangles. It
    is drawn as wide as `tab-width' says, so a line indented with tabs is
    shown further right than its columns, and the cursor where the text
    is.

EXAMPLES
    A Tab that inserts spaces after text, as it once did:

        (setq tab-always-indent nil)

    A Tab that completes once the line is indented:

        (setq tab-always-indent 'complete)

    Wider indentation in C, and shifting rather than reindenting there:

        (put 'c-mode 'tab-width 8)
        (put 'c-mode 'indent-region-style 'shift)

    Return as a plain newline, in every buffer:

        (define-key nil "<ret>" 'insert-newline)

    or in the buffer you are in only:

        (electric-indent-mode -1)

    Indent a macro of your own like defun:

        (put 'with-my-buffer 'lisp-indent 2)

    A rule for a mode of your own, which indents a line one Tab further
    than the one above when that one ends in a colon:

        (make-mode 'my-mode)
        (defun colon-indent ()
          (let ((above (previous-indentation))
                (line (line-number-at-point)))
            (if (and (> line 1)
                     (progn (goto-line (- line 1))
                            (string-match-p ":$" (current-line))))
                (+ above (indent-width))
                above)))
        (put 'my-mode 'indent-function 'colon-indent)
