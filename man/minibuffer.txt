NAME
    minibuffer - the prompt, its history, and asking from Lisp

DESCRIPTION
    A command that needs something from you -- a file name, a string to
    search for, a command's name -- asks for it in a prompt: as in Emacs, a
    row across the bottom of the frame, just above the echo area, with the
    question in front of where you type. The windows above give it the row
    and have it back when the prompt closes, so the text you are searching
    or editing stays in sight. Type the answer and press Return; Escape or
    C-g closes the prompt without answering.
    Tab completes what you have typed, as the `completion' page describes,
    and the arrow keys bring back what you answered at the same prompt
    before.

ANSWERING
        <ret>           answer with what is typed
        <esc>  C-g      close the prompt, answering nothing
        <tab>           complete what is typed
        <backspace>     delete the character before the cursor
        C-p  M-p  <up>  the answer given before this one
        C-n  M-n  <down>
                        the one after it

    The keys that move and edit in a buffer work in a prompt as well: C-a,
    C-e, C-f, C-b, C-k and C-y among them. While the strip of completions
    is showing, the first C-g puts it away and the second closes the
    prompt.

HISTORY
    Each prompt remembers the answers given to it, under its own question:
    M-x the commands you ran, C-x C-f the files you opened, M-: the
    expressions you evaluated. Two prompts that ask in the same words share
    one history. An empty answer is not remembered, and neither is the same
    answer twice running.

    C-p goes back one answer at a time and C-n forward again; one step past
    the newest brings back what you had half typed. A prompt keeps
    `history-length' answers, a hundred unless you change it, and 0 keeps
    none. The history is written when the editor quits and read back when
    it starts, unless `save-history' is nil: see `session'.

EVALUATING AN EXPRESSION
    M-: asks for a Lisp expression, evaluates it, and shows it in the echo
    area with its value, as (+ 1 2) => 3. One that fails shows !! and the
    error in place of => and the value. Both stay in the log, where C-h e
    finds them.

    The expression is evaluated as init.lisp is, outside any function, so
    what it defines -- a function, a variable, a command -- is the
    editor's from then on, and a function defined again works the new way
    at once. `eval-string-top-level' evaluates a string so from Lisp, and
    returns (t VALUE), or (nil WHY) when it fails.

    To evaluate a few expressions at a time, and keep them where they can
    be changed and evaluated again, use a buffer: see `repl'.

PREVIEWS
    While C-x r t asks for its string, what you type is drawn on every line
    of the block, and goes when you answer or close the prompt. It is drawn
    over the buffer, not put in it, so closing the prompt leaves the file as
    it was. `preview-commands' names the commands shown this way; each needs
    code of its own in preview.lisp to say what it would do.

ASKING FROM LISP
    `minibuffer-read' opens a prompt and returns at once. What is typed
    reaches a function of yours later, when Return is pressed:

        (minibuffer-read "Name:" (lambda (name) (message "Hello %s" name))
                         nil nil)

    ON-CONFIRM is called with the text when Return is pressed, and
    ON-CANCEL, when it is not nil, with nothing when Escape is. ON-CHANGE,
    when it is not nil, is what Tab asks for candidates: it is called with
    the text and returns a list of strings. MODE is the major mode the
    prompt is edited in, and so what its keys do -- an incremental search
    gives its own -- and KEY names the history it keeps, PROMPT itself when
    it is not given. Either may be nil, which is the same as leaving it
    out: (minibuffer-read PROMPT ON-CONFIRM nil nil nil KEY) names a
    history and keeps minibuffer-mode.

    A command that declares its arguments needs none of this: the editor
    asks for them, with these prompts, before it runs the command. See
    `keymaps'. `pending-command' says which command an open prompt is
    asking for, which is how a preview knows what to show. A background job
    cannot open a prompt: `minibuffer-read' refuses there.

THE MINIBUFFER WINDOW
    The prompt's window is `minibuffer-lines' rows high, one unless you
    change it, and the question is drawn in the `minibuffer-prompt' face.
    While it is open the other windows follow their point, as an incremental
    search needs. C-x o goes in and out of it; it cannot be split or closed
    with C-x 2, C-x 3 or C-x 0, C-x 1 in another window leaves it where it
    is, and `count-windows' does not count it.

REPLACING THE PROMPT
    `minibuffer-read' hands its arguments to the function
    `*minibuffer-read-function*' names, and every prompt in the editor goes
    through it, so a function of yours there replaces them all. The
    editor's own is `default-minibuffer-prompt', the window at the bottom
    described here. In it Return runs `minibuffer-confirm', Escape and C-g
    `minibuffer-cancel' and Tab `minibuffer-complete', and closing it runs
    `minibuffer-cleanup', which makes the buffer you were in current again.

    minibuffer.lisp has another, written in Lisp:
    `floating-minibuffer-prompt', a bordered window in the middle of the
    frame, titled with the question,
    `minibuffer-width' columns wide and `minibuffer-height' rows tall, its
    border included, or as much as the frame can hold. Name it in
    `*minibuffer-read-function*' to have every prompt open that way, or run
    `toggle-floating-minibuffer' to go from one to the other.

EXAMPLES
    Every prompt in a floating window, as a narrower one:

        (setq *minibuffer-read-function* 'floating-minibuffer-prompt)
        (setq minibuffer-width 40)

    A minibuffer two rows high, its question in yellow:

        (setq minibuffer-lines 2)
        (set-face 'minibuffer-prompt "yellow" nil '("bold"))

    A longer history at every prompt:

        (setq history-length 500)

    A question of your own, with Tab completing over three answers:

        (minibuffer-read "Colour:"
                         (lambda (colour) (message "You chose %s" colour))
                         (lambda (typed)
                           (fuzzy-filter typed '("red" "green" "blue")))
                         nil)

    Forget the commands M-x remembers:

        (clear-minibuffer-history "M-x")

    Define a function from Lisp as M-: would:

        (eval-string-top-level "(defun twice (n) (* 2 n))")
