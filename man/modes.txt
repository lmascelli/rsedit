NAME
    modes - what a buffer is being edited as, and what is on in it

DESCRIPTION
    Every buffer has one major mode, and the mode says what the buffer is
    edited as: how its text is coloured, what its brackets, strings and
    comments are, how Tab indents a line, which words C-M-i offers, and
    which keys do something of their own in it. The status line shows the
    mode's name, and C-h M describes it, with the keys it binds.

    A file gets its mode from its name, and a buffer that is not a file --
    a directory listing, a manual page, a list of matches -- from whatever
    made it. `set-major-mode' gives the current buffer another, as the
    `buffers' page says. Making a mode of your own is `writing-modes'.

    On top of its major mode a buffer can have minor modes on: features
    turned on and off in that buffer alone, such as auto-fill-mode, which
    breaks lines as you type. The status line shows each after the major
    mode's name, as fundamental-mode Fill.

MINOR MODES
    M-x visual-line-mode wraps words on screen without adding newlines to
    the buffer. It starts off; while on, its keys move through visual rows.
    See `wrapping' for navigation, scrolling and configuration.

    M-x and a minor mode's name turn it on in the buffer you are in, or
    off when it is on already; with C-u 1 before it, on, and with C-u -1,
    off. A minor mode can bind keys and run hooks of its own, which hold
    only in the buffers where it is on. Its keys come before those of the
    buffer's major mode and after a local keymap, such as vim's: the
    `keymaps' page has the whole order. Of two minor modes that bind the
    same key, the one turned on last wins. C-h M lists the minor modes on
    in a buffer, and C-h b the keys each of them binds.

    `define-minor-mode' makes one, with a command of the same name:

        (define-minor-mode shout-mode "Shout"
          "Upcase the words typed in this buffer.")

    LIGHTER, here Shout, is what the status line shows while it is on, and
    DOC documents the command; BODY, when there is one, runs after each
    time the command turns the mode on or off. The keys and the hooks are
    given as a major mode's, with the minor mode's name:

        (define-key 'shout-mode "C-c u" 'upcase-word)
        (add-hook 'shout-mode "post-self-insert-hook" 'my-shout)

    `minor-mode-on' and `minor-mode-off' turn one on and off from Lisp, in
    BUFFER or in the current buffer, `minor-mode-p' says whether it is on,
    and `minor-modes' lists those on, in the order they came on.
    `make-minor-mode' makes one with no command; `minor-mode-wanted-p' is
    how the command reads its argument.

    A buffer that gets a new major mode loses its minor modes, as in
    Emacs, all but read-only-mode, and gets those `minor-mode-enable'
    asks for in the new one:

        (minor-mode-enable 'auto-fill-mode 'fundamental-mode)

    turns auto-fill-mode on in every buffer that gets fundamental-mode
    from then on, and with no major mode in every buffer. Buffers in that
    mode already are left as they are.

    A module turns a minor mode on everywhere that way, through a global
    mode that starts on: show-paren-mode and whitespace-mode are, as
    A MINOR MODE IN EVERY BUFFER says. `minor-mode-disable' takes back what
    `minor-mode-enable' asked for with the same arguments, and leaves the
    buffers where the mode is on as they are:

        (minor-mode-disable 'whitespace-mode)

    in init.lisp, after the modules, keeps whitespace-mode off in every
    buffer but the first *scratch*, which is made before init.lisp is
    read. To keep a mode off in the buffers of one major mode only, turn
    it off from that mode's after-change-major-mode-hook, which runs once
    the minor modes asked for are on: the EXAMPLES have one.

A MINOR MODE IN EVERY BUFFER
    `define-globalized-minor-mode' makes a command that turns a minor
    mode on in every buffer at once, those open and those to come, and
    off in all of them:

        (define-globalized-minor-mode global-auto-fill-mode
          auto-fill-mode nil
          "Break lines as you type in every buffer.")

    M-x global-auto-fill-mode then turns auto-fill-mode on everywhere, and
    off again when it is on already; C-u 1 and C-u -1 before it mean on
    and off, as for a minor mode's own command. From Lisp,
    (global-auto-fill-mode 1) in init.lisp does the same, and the
    variable of the same name says whether it is on. DOC documents both.

    ON, when it is not nil, starts the global mode on: the mode is on in
    every buffer as soon as it is defined, without a word in the echo
    area. show-paren, whitespace, auto-revert and findings define their
    global modes that way, global-show-paren-mode, global-whitespace-mode,
    global-auto-revert-mode and global-findings-mode, and
    (global-show-paren-mode -1) in init.lisp, after the modules, turns
    show-paren-mode off everywhere.

    With TURN-ON nil, as above, the mode is asked for in every buffer with
    `minor-mode-enable', and taken back with `minor-mode-disable' when the
    global mode is turned off: it is on before a major mode's
    after-change-major-mode-hook runs, which can still turn it off in the
    buffers of that mode.

    Otherwise TURN-ON chooses the buffers. It names a function of no
    arguments, which is called with each buffer current and turns the
    mode on there, or leaves it off; the EXAMPLES have one that takes
    only the buffers visiting a file. It runs after the major mode's
    hooks, for every buffer made. Write it with `minor-mode-on' and
    not with the mode's own command, which says in the echo area what it
    did, for every buffer made. It is the name of a function, as for a
    hook: a lambda is refused.

    Off means off everywhere: turning the global mode off turns the mode off
    in the buffers that had it on by hand, or from `minor-mode-enable', as
    well. What `minor-mode-enable' asked for one major mode stays, for the
    buffers of that mode made from then on. While it is on, a buffer can still
    turn the mode off for itself, and has it back with its next major mode, or
    the next time the global mode is turned on.

BUFFER ROLES
    Besides its major mode, every buffer has a role, which says what the
    buffer is for: editing, for a file or *scratch*; prompt, for the line a
    question is answered on; completion, for the list of candidates; view,
    for something to look at; and document-view, for a text to read, which
    is a view. A buffer gets its role when it is made, before any of its
    hooks runs, and keeps it whatever its major mode becomes. (buffer-role)
    says which it is, and `buffer-role-derived-p' whether a role is another
    or derives from it.

    The role is given where the buffer is made: :role to `buffer-create'
    and `make-floating-window', editing when it is not given, and to
    `minibuffer-read', prompt when it is not. What the editor makes has
    the role it is for: a file, *scratch* and the *risp* buffer are
    editing; the prompt, floating or not and whatever its major mode, an
    incremental search's included, is prompt; the list of candidates, at a
    prompt or in a buffer, is completion; the help and the manual pages are
    document-view; Dired, the buffer list, the theme list, the findings
    list, the results of occur and grep, a build's output and a shell
    command's, the logs and locations of LSP, *Messages* and *Backtrace*
    are view.

    The role decides which minor modes the buffer admits. An editing
    buffer admits every one; the other roles admit only those permitted
    for them, and document-view, where it has no rule of its own, those
    permitted for view. Of two rules for the same role, the one in your
    configuration wins over the one the editor ships with. read-only-mode
    goes in every role.

    The editor ships with three permissions: show-paren-mode in prompt, so
    that the brackets of an expression typed at M-: pair; visual-line-mode
    in document-view, so that the help and the manual pages wrap under
    global-visual-line-mode; and vim-mode in view, so that M-x vim-mode
    gives Vim's keys to a listing or the help, as the `vim' page says. Every
    other minor mode it ships -- electric-indent-mode, electric-pair-mode,
    whitespace-mode, auto-revert-mode, findings-mode, hl-line-mode,
    display-line-numbers-mode, auto-fill-mode, overwrite-mode, subword-mode,
    lsp-mode and the others -- has no rule, and so goes in editing buffers
    only. lsp-mode asks, besides, for a file and a server for its major
    mode, as before.

    A minor mode the role does not admit is not turned on: its command
    says why in the echo area and does nothing else, `minor-mode-on'
    returns nil, as it does for a mode on already, and
    `minor-mode-refusal' returns the reason, or nil where the mode is
    admitted. A rule of `minor-mode-enable' and a global mode pass such a
    buffer over without a word, and a global mode does not call its
    TURN-ON there. A mode permitted later is admitted from the next time
    it is asked for; one no longer admitted is turned off in the buffers
    where it was on, running its hook as for any other way off.

YOUR OWN ROLES AND RULES
    (define-buffer-role NAME :parent ROLE) makes a role of your own,
    deriving from ROLE, and returns NAME. A buffer of it answers for a
    minor mode as the nearest role of its lineage with a rule for that
    mode, its own first; with no rule anywhere, a role that derives from
    editing admits the mode and any other does not. Without :parent the
    role is a root of its own, open to nothing that is not permitted for
    it. Defining a role again the same way changes nothing, and so does
    loading the same configuration twice; defining it with another
    parent is an error, the roles the editor ships included, since a
    buffer keeps its role for life. A parent that is no role, a keyword
    given twice or one it does not take is an error too, and nothing is
    defined.

    (set-minor-mode-policy MODE POLICY :role ROLE) is your rule for MODE
    in ROLE, and in the roles that derive from it and have none of their
    own. POLICY is allow, deny or inherit: inherit takes your rule for
    ROLE back, so that the one the editor ships for ROLE, if any, or else
    the role ROLE derives from, decides. For the same role your rule wins
    over the editor's. An allow turns nothing on: the mode is admitted
    from the next time it is asked for. A deny turns MODE off, with its
    hook, wherever it is on and no longer admitted. MODE must be a minor
    mode and ROLE a role; a call wrong anywhere changes nothing.
    (minor-mode-allowed-p MODE) says whether the current buffer admits
    MODE, of another buffer when it is given one, and of a role with
    :role.

    Suppose your logs are read in a mode of your own, and you want the
    line under the cursor lit there, as in no other view. Give the log
    buffers a role of their own, deriving from view, so that whatever
    view admits they admit too, and permit hl-line-mode in it alone:

        ;; init.lisp
        (define-buffer-role 'log-view :parent 'view)
        (set-minor-mode-policy 'hl-line-mode 'allow :role 'log-view)
        (make-mode 'log-mode)
        (minor-mode-enable 'hl-line-mode 'log-mode)

        (defcommand open-log () nil
          "Show the log buffer."
          (switch-to-buffer
           (buffer-create "*log*" :mode 'log-mode :role 'log-view)))

    (minor-mode-allowed-p 'hl-line-mode :role 'log-view) is then t, and
    with :role 'view nil: the rule is log-view's, and a view has none of
    its parent's. hl-line-mode comes on in *log* with log-mode, since
    log-view admits it, and not in a buffer of log-mode made with :role
    'view. A rule given to view later reaches log-view as well,
    wherever log-view has none of its own. Taking the permission back,
    with (set-minor-mode-policy 'hl-line-mode 'deny :role 'log-view),
    turns hl-line-mode off in *log* at once.

WHICH MODE A FILE GETS
        rust-mode           .rs
        c-mode              .c .h
        cpp-mode            .cpp .hpp .cc .hh .cxx .hxx .c++ .h++ .C .H
                            .ipp .tpp .ixx .cppm
        risp-mode           .lisp .risp
        python-mode         .py .pyw .pyi
        toml-mode           .toml, and Cargo.lock
        bash-mode           .sh .bash .bashrc .bash_profile .bash_login
                            .bash_logout .profile
        cmake-mode          CMakeLists.txt .cmake
        fundamental-mode    any other name

    `add-auto-mode' adds a name to these. PATTERN is a regular expression
    matched against the file's whole path, so it can name a directory as
    well as an extension. The first pattern declared that matches is the
    one that counts, and the modules declare theirs as they load: a pattern
    of yours that takes a name from one of them goes at the top of
    init.lisp, before the modules. MODE need not exist yet.

    The mode is chosen when the file is opened, and again when C-x C-w
    writes the buffer under a name that another pattern claims. A name no
    pattern claims leaves the mode as it was.

    A .h file is C. To open headers as C++, put this at the top of
    init.lisp, before the modules, since the first pattern declared wins:

        (add-auto-mode "\\.h$" 'cpp-mode)

    A script without a recognized extension can be switched explicitly:

        (set-major-mode 'bash-mode)

MODES THAT SHIP
        fundamental-mode    plain text: no colours, no keys of its own
        rust-mode           Rust
        c-mode              C source and headers
        cpp-mode            C++ source, headers and module interfaces
        python-mode         Python source and type stubs
        toml-mode           TOML configuration and Cargo.lock
        bash-mode           Bash and Bourne-style shell scripts
        cmake-mode          CMake build scripts
        risp-mode           this editor's own Lisp
        dired-mode          a directory listing
        buffer-list-mode    the list of buffers
        compilation-mode    the output of a build
        occur-mode          a list of matches
        shell-output-mode   what a shell command printed
        help-mode           an answer from C-h
        manpage-mode        a page of this manual
        theme-list-mode     the list of themes
        backtrace-mode      where an error came from
        minibuffer-mode     a prompt
        isearch-mode        the prompt of an incremental search
        completion-mode     the strip of candidates

    In the buffers the editor makes to show you something -- the listings,
    the help, the manual -- n and p go down and up, a line at a time or in a
    build's output a complaint at a time, and q puts the buffer away. g
    reads dired, the buffer list and the theme list again, and runs a build
    again. A key a mode does not bind does what it does everywhere else, so
    C-x C-f works in a directory listing.

THE LANGUAGES
    Each language mode colours the keywords, strings and comments of its
    language, and tells the editor its brackets, strings and comments,
    which C-M-f and M-; go by. Each colours more of its own:

        rust-mode     numbers, types, functions, doc comments, attributes
        c-mode        numbers, types, functions, doc comments, the
                      preprocessor
        cpp-mode      what c-mode does, and attributes
        python-mode   numbers, types, functions, decorators
        risp-mode     numbers, functions and macros, the names defined
        toml-mode     numbers, dates, keys, table headers
        bash-mode     builtins, variables, functions, heredocs
        cmake-mode    commands, variables, generator expressions,
                      bracket arguments and bracket comments

    All of them but rust-mode indent as their language does, as the
    `indentation' page says; in rust-mode Tab matches the line above.

    Their words are lists you can read: `rust-keywords', `rust-constants'
    and `rust-types'; `c-keywords', `c-constants' and `c-types';
    `cpp-keywords', `cpp-constants' and `cpp-types'; `python-keywords',
    `python-constants', `python-builtins' and `python-types';
    `toml-constants'; `bash-keywords' and `bash-builtins';
    `cmake-keywords', `cmake-commands', `cmake-constants' and
    `cmake-operators'; `risp-special-forms' and `risp-constants'. C-M-i
    offers them as
    keywords. The colouring and what C-M-i offers are both made from the
    lists when the module loads, so changing a list afterwards changes
    neither.

    risp-mode does not list the functions and macros it colours: it asks
    the interpreter, which knows every one there is, yours included. It
    asks when it loads, so a function defined since is coloured once M-x
    risp-refresh-vocabulary has asked again. C-M-i asks every time, and
    needs nothing.

LANGUAGE CONFIGURATION
    An existing init.lisp is not rewritten by an editor upgrade. Load the
    modules there; each loads the ones it needs first:

        (require 'cc-mode)
        (require 'python-mode)
        (require 'toml-mode)
        (require 'bash-mode)
        (require 'cmake-mode)

    C/C++ include C11/C23 and modern C++ vocabulary, preprocessor directives,
    attributes, numeric suffixes and character literals. C++ raw strings
    with an empty tag or raw, tag, json, xml, sql and glsl are recognized.
    Register another literal delimiter in both engines with:

        (cpp-add-raw-string-delimiter "shader")

    Bash heredocs ending in EOF, EOT and END are coloured across lines.
    Another literal marker can be added with:

        (bash-add-heredoc-delimiter "SCRIPT")

    CMake commands are coloured in any case, IF( as if(, and only where a
    call follows: in set(if 1) the if is an argument. `cmake-keywords' are
    the commands of blocks, `cmake-commands' the others most written, and
    any other name before a ( is coloured as a function of your own.
    `cmake-constants' and `cmake-operators' are coloured in capitals only,
    as CMake writes them in a condition.

    The Bash indenter recognizes literal word heredoc markers independently
    of this colouring registration, including quoted markers and <<-.
    See `indentation' for the language-specific rules and their limits.

HOOKS
    A hook is a list of functions the editor calls at a moment of its own,
    named by a string:

        pre-command-hook        before every command
        post-command-hook       after every command that did not fail
        post-self-insert-hook   after a key that types itself, before
                                post-command-hook; not after a paste
        buffer-created-hook     a buffer has just been made
        major-mode-hook         a buffer has its mode: it has just been
                                made, or its mode has just changed
        after-change-major-mode-hook
                                after major-mode-hook, once the minor
                                modes `minor-mode-enable' asks for are on
        find-file-hook          a file has been opened in a new buffer,
                                after those three
        before-save-hook        before a manual save copies the text;
                                a failure aborts it, as `files' describes
        after-save-hook         a manual save has written the file,
                                C-x C-w included, as `files' describes
        after-revert-hook       a buffer has read its file again: after
                                M-x revert-buffer, or on its own when
                                the file changed, as `files' describes
        after-set-visited-file-name-hook
                                C-x C-w has written the buffer to a file
                                it was not visiting
        after-close-hook        a buffer has been closed; closed-buffer-name
                                and closed-buffer-file say which
        minor-mode-hook         a minor mode has just been turned on, or
                                off, in a buffer
        kill-editor-hook        the editor is exiting, before the
                                processes still running are stopped

    (add-hook 'rust-mode "find-file-hook" 'my-rust-setup) calls the function
    my-rust-setup, with no arguments, when a Rust file is opened; nil in
    place of the mode calls it whatever the mode. FUNCTION is the name of a
    function: a lambda is refused. The functions run in the order they were
    added: the major mode's own, then those of each minor mode on in the
    buffer, then those for every mode, with the buffer concerned current;
    after-close-hook runs those of the closed buffer's modes, once it has
    gone: no buffer is the closed one then, so closed-buffer-name holds its
    name and closed-buffer-file the file it visited, or nil, while the hook
    runs. A minor mode's minor-mode-hook runs for that mode alone, and
    (minor-mode-p) inside it says which way it went. A function added
    twice runs once.

    `remove-hook' takes the same arguments: with a mode it takes the
    function off that mode's hook, and with nil off the one for every mode.
    A function that fails is reported in the log, and the others still run,
    except in before-save-hook, where the first error aborts the save.
    The first *scratch* is made before init.lisp is read, so the hooks of
    a new buffer that init.lisp adds do not run for it.

    kill-editor-hook runs only the functions added with nil, and gives
    them one second, together with the processes they tell to finish by
    closing their input: the editor waits for those to end, and for no
    others. Past the second the functions left do not run, and the
    processes still there are stopped, as every other one is. A function
    that is running is not cut short. The hook does not run when the
    editor exits by a crash.

LIMITS
    Loading a mode's file again makes the mode again, empty: the keys and
    hooks other files gave it go, electric-pair's among them.

    A minor mode is on in one buffer at a time. One that holds everywhere,
    asked for with `minor-mode-enable' or made global with
    `define-globalized-minor-mode', is still turned on buffer by buffer:
    a buffer that turns it off gets it back with its next major mode. A
    global mode does not remember which buffers had the mode on before
    it: turned off, it turns the mode off in all of them. A minor mode's
    command called from Lisp with no argument turns the mode the other
    way, where Emacs would turn it on: write (auto-fill-mode 1). A buffer
    losing its minor modes to a new major mode runs none of their hooks.

    Colouring uses regular expressions, not a compiler or a full parser.
    Python f-strings and shell strings are coloured uniformly, including
    interpolation. Python match and case are treated as keywords everywhere.
    Arbitrary C++ raw-string tags and Bash heredoc markers need the explicit
    colouring registrations above: the regexp engine has no backreferences.
    The Bash structural scanner treats # as a comment opener even inside an
    unquoted word or parameter expansion; the indenter has its own shell
    lexer and does not have that limitation. Shebangs are not mode selectors.
    CMake bracket arguments and bracket comments are recognized with up to
    two = between their brackets, [==[ ... ]==]; one with more is read as
    ordinary arguments, by the colouring and by C-M-f alike.

EXAMPLES
    Open .ino files as C++, at the top of init.lisp:

        (add-auto-mode "\\.ino$" 'cpp-mode)

    Say which file has been opened, whatever its mode:

        (defun my-opened () (message "Opened %s" (current-buffer)))
        (add-hook nil "find-file-hook" 'my-opened)

    And stop saying it:

        (remove-hook nil "find-file-hook" 'my-opened)

    Tell a process started with `process-start' to finish when the
    editor exits, rather than having it stopped:

        (defun my-repl-bye ()
          (process-send 'my-repl "(exit)\n")
          (process-close-input 'my-repl))
        (add-hook nil "kill-editor-hook" 'my-repl-bye)

    Say which file a closed buffer was visiting:

        (defun my-closed ()
          (when closed-buffer-file
            (message "%s was %s" closed-buffer-name closed-buffer-file)))
        (add-hook nil "after-close-hook" 'my-closed)

    Break lines as you type in every C and C++ comment:

        (minor-mode-enable 'auto-fill-mode 'cpp-mode)

    Draw no paired brackets in the buffers of one mode, where
    show-paren-mode is otherwise on:

        (defun my-no-parens () (minor-mode-off 'show-paren-mode))
        (add-hook 'help-mode "after-change-major-mode-hook" 'my-no-parens)

    A command that numbers the lines of every buffer visiting a file,
    and of no other, and that command run at startup:

        (defun my-number-files ()
          (if (buffer-file-name)
              (minor-mode-on 'display-line-numbers-mode)))
        (define-globalized-minor-mode my-number-files-mode
          display-line-numbers-mode my-number-files
          "Number the lines of every buffer visiting a file.")
        (my-number-files-mode 1)

    A key only while auto-fill-mode is on:

        (define-key 'auto-fill-mode "C-c q" 'fill-paragraph)

    Colour the Lisp functions defined since risp-mode loaded:

        (risp-refresh-vocabulary)

    How many keywords rust-mode knows:

        (length rust-keywords)
