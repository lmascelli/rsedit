NAME
    passwords - asking for a password without showing it, and keeping one

SYNOPSIS
    (read-passwd PROMPT ON-CONFIRM &optional CONFIRM DEFAULT &key ...)
    (read-passwd-confirm)
    (read-passwd-self-insert STRING)
    (read-passwd-delete-backward-char)
    (read-passwd-delete-char)
    (read-passwd-kill-line)
    (read-passwd-erase)
    (read-passwd-yank)
    (read-passwd-toggle-visibility)
    (process-send-password NAME PROMPT &key ...)
    (password-read PROMPT ON-CONFIRM &optional KEY &key :on-cancel)
    (password-read-and-add PROMPT ON-CONFIRM &optional KEY &key ...)
    (password-read-from-cache KEY)
    (password-in-cache-p KEY)
    (password-cache-add KEY PASSWORD)
    (password-cache-remove KEY)
    (password-reset)
    read-hide-char
    password-cache
    password-cache-expiry

DESCRIPTION
    A password is asked for in the minibuffer, as any other answer is, and
    typed there as any other is; but it is not shown. Each character you
    type is drawn as a *, and the password itself is kept apart from the
    prompt's buffer, where nothing else in the editor looks:

        Password: ******

    Return gives it to whatever asked for it, and Escape or C-g closes the
    prompt without giving it. Tab shows what you have typed, to check it,
    and hides it again.

    A program running in `eshell' that asks for a password, as sudo -S
    does, is answered the same way: see the `eshell' page.

TYPING A PASSWORD
    Typing puts a character where the cursor is, and the keys that move
    in a line move over the stars: C-a, C-e, C-b, C-f and the arrows.

        <ret>           give the password
        <esc>  C-g      close the prompt, giving nothing
        <tab>           show the password, or hide it again
        <backspace>     delete the character before the cursor
        C-d  <delete>   delete the character after it
        C-k             delete from the cursor to the end
        C-u             delete the whole password
        C-y             put the latest kill where the cursor is

    A paste goes into the password too, without its line breaks, so that
    a password copied with the line it was on comes without the newline.
    C-u is the prompt's own here, as in Emacs and at a terminal, and not
    the prefix argument.

WHERE IT DOES NOT GO
    The prompt's buffer has only the stars in it, or, while Tab shows the
    password, the password; and it is read-only, its text put there
    without an undo record. So:

    - nothing typed at the prompt goes on the kill ring, or to the system
      clipboard with it: C-w, M-w and the other kills say so, and kill
      nothing; C-k deletes without killing;
    - nothing of it can be undone, or brought back, in the buffer;
    - no history keeps it: M-p brings back nothing, and nothing of it is
      written in the session file;
    - a keyboard macro recorded meanwhile has none of the keys typed at
      the prompt, Return included. Replaying it stops when it reaches the
      prompt, which is left open for you to answer; a macro is not
      replayed in one;
    - the characters it was made of are overwritten as they are deleted,
      and the rest once it has been given or the prompt closed; but not
      what Tab showed, which was the buffer's text for a while.

    What is done with the password once it is given is up to whatever
    asked: `read-passwd' hands it to a function as an ordinary string,
    which stays in memory until nothing uses it.
    `process-send-password' never makes a string of it.

ASKING FROM LISP
    `read-passwd' opens the prompt and returns at once. The password
    reaches a function of yours later, when Return is pressed:

        (read-passwd "Password: "
                     (lambda (password) (my-connect password)))

    With CONFIRM, the password is asked for twice, the second time as
    "Confirm password: ", and when the two differ the prompt says so and
    starts again from the first. DEFAULT is what an empty answer stands
    for. Each may be given in its place or after its keyword, :confirm
    and :default, not both; :on-cancel is called, with no arguments, when
    the prompt is closed without an answer.

    The prompt is opened as every other is, by the reader in
    `*minibuffer-read-function*', in read-passwd-mode: the floating
    minibuffer reads a password as the one at the bottom does. A reader
    of your own must open its buffer in the mode it is given, since a
    password typed in another would be shown: `read-passwd' says so as an
    error, and closes the prompt. As any prompt, it cannot be opened
    while another is open, or from a background job.

    `read-hide-char' is what is drawn for each character: "*" unless you
    change it. nil, or the empty string, draws nothing, as a terminal
    does; then the cursor stays at the end, and only Backspace, C-u and
    typing edit the password. Unlike Emacs', it is a string, not a
    character.

TO A PROCESS
    `process-send-password' asks for a password and writes it to the
    input of a process the editor talks with, followed by a newline: the
    password goes from where the prompt keeps it to the process, and
    never becomes a string of Lisp's.

        (process-send-password 'my-tool "Passphrase: ")

    :newline is what follows it, "\n" unless you give another, or nil
    for nothing; :confirm asks twice, as `read-passwd' does. :on-sent is
    called with t once it is written, or with nil when the process was
    not reading; :on-cancel when the prompt is closed instead. With no
    such process it asks nothing, and returns nil.

THE CACHE
    A password asked for again and again -- for each file of a server, for
    each run of a tool -- can be kept for a while, by a key you choose,
    such as the name of the server.

    `password-read' looks in the cache first: what it keeps under KEY
    goes to ON-CONFIRM at once, and only when it keeps nothing is the
    password asked for. What is typed is not kept: add it with
    `password-cache-add' once you have seen it work, and take a password
    that did not work out with `password-cache-remove'.
    `password-read-and-add' keeps it at once, when KEY is not nil.

    A password stays `password-cache-expiry' seconds from when it was
    added, 16 unless you change it, and nil keeps it until it is removed.
    An expired one is never given, and is overwritten at the next key
    pressed. `password-reset', and M-x password-reset, forgets them all.
    With `password-cache' nil, nothing is kept and nothing kept before is
    found. The cache is the editor's for this run only.

LIMITS
    Only the editor's own commands are kept from the password: Lisp of
    yours can read the prompt's buffer while the password is shown, and
    has the password itself once it is given.

    A program that reads a password from the terminal rather than from
    its input -- ssh, git over https, sudo without -S -- does not find
    one, since a program the editor runs has no terminal: see the
    `processes' page.

EXAMPLES
    A password checked on the way in, asked twice:

        (read-passwd "New password: "
                     (lambda (password)
                       (message "%d characters" (length password)))
                     t)

    Dots instead of stars:

        (setq read-hide-char "•")

    Nothing drawn at all, as sudo does at a terminal:

        (setq read-hide-char nil)

    A password asked for once and remembered for five minutes:

        (setq password-cache-expiry 300)
        (password-read-and-add "Password for the server: "
                               'my-connect "server")

    Forget a password that did not work:

        (password-cache-remove "server")

    <esc>                   minibuffer-cancel
    C-g                     minibuffer-cancel

    <delete>                read-passwd-delete-char
    C-d                     read-passwd-delete-char
    C-k                     read-passwd-kill-line
    C-u                     read-passwd-erase
    C-y                     read-passwd-yank
