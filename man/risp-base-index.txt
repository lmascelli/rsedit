NAME
    risp-base-index - every base function and special form of Risp

DESCRIPTION
    Every function installed by setup_base_env, grouped by what it is for,
    with a few words on each. This page is a map of the base interpreter.
    Applications may install additional functions of their own.

    A plain function evaluates its arguments before it is called. A special
    form controls their evaluation itself; those forms have a separate
    section below and are not entries in all-functions.

    For a function's call signature and complete documentation, use
    (function-doc 'NAME). function-arglist reports a Lisp closure's declared
    parameters; native signatures are in their documentation strings.
    In rsedit, C-h f on a function name opens its help.

    There are 87 base function names, including aliases, and 28 special
    form names in this version. Native functions supplied by an embedding
    application are not included.

  ARGUMENTS AND VALUES
    nil is both false and the empty list. Every other value is true,
    including zero and an empty string. t and keyword symbols such as
    :ready evaluate to themselves.
  
    Functions, macros and variables occupy separate namespaces. Closures
    capture lexical environments. Parameter lists accept required names,
    &optional names and one &rest name; t, nil and keywords are not valid
    parameter names.
  
    Numbers are f64 values. This interpreter does not have a separate
    arbitrary-precision integer type. String positions and lengths count
    Unicode scalar values, not bytes or grapheme clusters. Sequence indices
    start at zero. Vectors and maps have literal syntax; the base library
    does not register functions named vector or make-hash-table.
  
  CURRENT BEHAVIOR
    This page describes Risp, rather than promising Emacs Lisp compatibility.
  
    eq and eql compare numbers and symbol names by value. Allocated compound
    values compare by identity; native primitives use their function address.
    equal compares data structurally and closures by identity.
  
    memq and assq currently use structural comparison, just as member and
    assoc do. member and memq build a new list tail rather than returning
    the original tail by identity.
  
    add-to-list accepts additional elements, not an Emacs-style APPEND
    flag. The named-list update functions currently write their result in
    the calling environment; account for this when calling them in a
    nested lexical scope.
  
    backquote handles proper syntax lists and vectors. Dotted templates,
    maps and nested backquote levels are not fully expanded. The reader's
    comma and comma-at spell unquote and unquote-splicing inside templates;
    they are not independently registered functions.
  
    A fiber yields only where the evaluator can retain a continuation.
    Unsupported positions signal YieldNotAllowed; condition-case does not
    intercept this error. resume on a running fiber returns nil without
    changing its state. A completed or failed fiber is done.
  
    spawn currently returns an empty syntax form and exposes no Lisp join
    operation. defconst initializes a binding but does not make it immutable.
    unwind-protect attempts its cleanup; a host-imposed execution budget
    can still prevent cleanup from finishing.
  
    format supports %s, %S, %d, %f and %%. Both %s and %S currently use
    display formatting. It copies backslashes literally; the reader handles
    escapes in string literals. %d truncates a finite number toward zero.
  
    string-to-number currently accepts the forms recognized by Rust's f64
    parser, including scientific notation and non-finite values. The Lisp
    reader does not accept all of those same numeric spellings. substring
    clamps out-of-range indices after interpreting negative ones from the end.
