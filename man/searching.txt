DESCRIPTION
    C-s finds text as you type it, and M-% replaces it, asking at each
    place. M-s o lists every line of this buffer that matches, M-s g every
    line of the files under a directory, and M-g n and M-g p go from one
    listed place to the next while you work. Each has a form that takes a
    regular expression instead of plain text; the `regexps' page says how
    one is written.

SEARCHING AS YOU TYPE
        C-s             search forward
        C-r             search backward
        C-M-s  C-M-r    the same, for a regular expression

    C-s opens a prompt, and each character typed into it moves to the first
    match of what has been typed so far, selected; Backspace takes the last
    character back. Inside the search:

        C-s  C-r        go on to the next match forward, or backward
        <ret>           stop, leaving the cursor at the match
        C-g  Escape     stop, and go back to where the search started

    A search that runs out says Failing, and pressing C-s once more starts
    again from the top of the buffer, C-r from the bottom. A regular
    expression still being typed, such as [a-, reads as a failing search
    until it is complete.

    Case is ignored unless `case-fold-search' is nil: a search for the
    finds The and THE, and so does a search for The.

REPLACING
        M-%             replace text, asking at each match
        C-M-%           the same, for a regular expression

    M-% asks what to replace and what with, then stops at each match:

        y               replace this one, and go on
        n               leave this one, and go on
        !               replace this one and all the rest
        ^               take back the last one replaced
        q               stop here

    Any other key stops too, and then does what it always does: Return
    stops and breaks the line, C-g stops and does nothing more. Each
    replacement is undone on its own by C-/.

    Replacing goes from the cursor to the end of the buffer, or through the
    region when there is one: go to the top first to do a whole buffer.
    M-x replace-string and M-x replace-regexp replace every match there
    without asking, and say how many they replaced.

    The replacement takes the case of what it replaces: replacing colour
    with color turns Colour into Color and COLOUR into COLOR, and leaves
    any other mix of cases as typed. Set `case-replace' to nil to have it
    put in as typed every time. Which matches are found follows
    `case-fold-search', as searching does.

    In the replacement of C-M-%, \1 to \9 stand for what the groups of the
    pattern matched, \& and \0 for the whole match, and \\ for a backslash.

    How the question is asked can be replaced. `*replace-read-function*'
    names a function, called with no arguments at each match, that shows
    the match its own way and answers with `replace-this', `replace-skip',
    `replace-rest', `replace-back', `replace-done' or `replace-abandon'.
    `replace-match' says what is on offer, and `replace-count' how many
    have been replaced.

EVERY MATCH AT ONCE
        M-s o           list the lines of this buffer that match
        M-s g           list the matching lines of every file under the
                        directory the editor was started in

    The list goes in a buffer of its own, one line for each match:

        TODO in notes.txt
        notes.txt:1: TODO: ask about the deadline
        notes.txt:7: TODO later
        --- 2 matches ---

    In it:

        <ret>           go to the match on this line
        o               go to it, and come back to the list
        n  p            down and up a line
        q               close the list's window
        C-c C-k         stop a search of files that is still going

    M-x occur-regexp and M-x grep-regexp take a regular expression, and
    M-x grep-in asks which directory to search. Each search makes a new
    list -- *Occur*, *Occur*<2>, *Grep* -- and the old ones stay until they
    are killed.

    A search of files runs while you go on working, and the list fills in
    as the files are read; its last line says how many matched. A file
    open with unsaved changes is searched as you have it, not as it is on
    disk. Files that are not text are left out, and so are seventeen
    directories that are large and generated, .git, target, build and
    node_modules among them. The search stops at 20000 files or 10000
    matches, and its last line says it stopped early; so does C-c C-k,
    which keeps what was found. Killing the list stops the search as well.

WALKING A LIST
        M-g n           go to the next place in the list
        M-g p           go to the place before

    M-g n and M-g p walk the newest list -- a search's or a compilation's
    -- from wherever you are, opening each place in the window you are in.
    The line is marked in the file, and the entry in the list. At either
    end they say so rather than starting again. M-x results-select, in an
    older list, makes that one the list they walk.

LIMITS
    The list of M-s o and M-s g opens in a strip along the bottom, and
    also takes the place of your buffer in the window you were in; C-x b
    brings your buffer back. For the same reason o opens the match and
    puts the list straight back over it. M-g n, from your buffer, is the
    way to go through a list without losing sight of either.

    M-s g does not read .gitignore, and the directories it leaves out are
    fixed: `find-file-recursive-ignore' does not change them. Searching a
    buffer only highlights the match the cursor is on, not every match.

LISTS FROM LISP
    A list of places is a set of entries attached to a buffer, and any code
    can make one: `results-put' attaches entries to a buffer and makes it
    the list M-g n walks. An entry is

        (KIND SOURCE LINE COLUMN OFFSET TEXT MATCH-START MATCH-END)

    where KIND is "file" or "buffer", SOURCE a path or a buffer's name,
    LINE counts from 1 and COLUMN from 0, OFFSET is where the match starts
    in the whole text, TEXT is its line, and the last two say where the
    match is within that line. All but KIND and SOURCE may be left off.
    `results-count', `results-entry' and `results-state' read a list,
    `results-visit' goes to one of its places, and `results-buffer' names
    the list M-g n walks. `occur-header-lines' is how many lines of a list
    come before its first match.

    A list that grows while it is walked, as a compilation's does, keeps a
    function under the buffer property results-refresh, with `buffer-put':
    it is called with the buffer's name before each step of M-g n.

EXAMPLES
    Match case exactly when searching and replacing:

        (setq case-fold-search nil)

    Put replacements in exactly as typed:

        (setq case-replace nil)

    Replace every tab in the buffer with four spaces:

        (progn (goto-char 0) (replace-string "\t" "    "))

    A key that lists the TODO lines of the buffer:

        (define-key nil "C-c o" '(occur "TODO"))

    A taller window for the lists:

        (setq occur-window-height 20)

    Put the places a linter reported in a list M-g n walks:

        (results-put "lint" "the project"
                     '(("file" "src/main.rs" 12 4)
                       ("file" "src/lib.rs" 3)))
