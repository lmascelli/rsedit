NAME
    session - what the editor keeps from one run to the next

SYNOPSIS
    (recent-files)
    (clear-recent-files)
    (find-recent-file)
    (session-value NAME &optional DEFAULT)
    (set-session-value NAME VALUE)
    save-history
    recent-files-length
    save-place
    session-save-interval

DESCRIPTION
    The editor writes down three things, when it quits and every minute
    while it runs, and when it starts it reads them back:

        the answers given at each prompt, which C-p walks back through
        the files opened, newest first, which M-g r opens again
        where point was in each file, which is where the file opens

    So M-x then C-p offers the command you ran last time, C-x C-f then C-p
    the file you opened last, and a file you were reading opens on the line
    you left it at. Each of the three can be turned off on its own.

    Lisp code -- your init.lisp, a module, a plugin -- can keep values of
    its own there too, each under a name: see VALUES KEPT BY NAME.

    They are kept in one file, `session', in the state directory: the
    `configuration' page says where that is. The file is the editor's:
    deleting it loses this memory and nothing else.

WHEN IT IS WRITTEN
    The file is written when the editor quits, and, while it runs, every
    `session-save-interval' seconds, 60 unless you change it, when there
    is something new to write. So an editor that is killed, or that stops
    on an error of its own, loses at most the last minute of its memory.
    nil, or a number under 1, writes the file only at exit.

    Several editors open at once share the file. Each, before it writes,
    reads what the others have added since it last looked, and takes it
    in behind what it knows itself: the answers another editor was given
    turn up at this one's prompts, after its own, and the files another
    opened among its recent files. What an editor forgets on purpose --
    with `clear-recent-files', or by leaving a file at its start -- it
    does not take back from the file it wrote itself.

THE ANSWERS AT THE PROMPTS
    Each prompt keeps its own answers, as the `minibuffer' page says, up to
    `history-length' of them. With `save-history' on, the default, every
    prompt's answers are written at exit and read back at the next start.
    With it nil they last one run.

    Everything typed at a prompt is written, a shell command at M-! and an
    expression at M-: included. The file is made readable by its owner
    only; `clear-minibuffer-history' forgets one prompt's answers before
    they are written, and (setq save-history nil) keeps them all off the
    disk.

THE RECENT FILES
    Every file opened with C-x C-f, or by any command that opens one, goes
    to the front of the list, and so does one saved under a new name with
    C-x C-w. A file opened again moves to the front; it is never listed
    twice. `recent-files' returns the list, newest first, as absolute
    paths, and keeps `recent-files-length' of them, 50 unless you change
    it; 0 keeps none.

    M-g r asks for one of them. Tab shows them all, the newest first, and
    typing narrows the list by any part of the path, as C-x b does with
    buffers; Return opens the one chosen. A file deleted since it was
    opened is still listed, and opening it gives an empty buffer, as
    C-x C-f does with a path that does not exist.

    `clear-recent-files' empties the list; the places stay.

WHERE POINT WAS
    With `save-place' on, the default, closing a buffer visiting a file
    remembers where point was in it, and so does quitting, for every such
    buffer still open. The next time the file is opened, in this run or a
    later one, point goes back there, before `find-file-hook' runs, and
    the window shows that line. A file that has become shorter opens at
    its end. Point at the very start is not remembered, since that is
    where a file opens anyway. The last 400 files are remembered, whether
    or not they are still among the recent files.

    With `save-place' nil every file opens at its start, and nothing is
    written.

VALUES KEPT BY NAME
    (set-session-value NAME VALUE) keeps VALUE under NAME, a symbol or a
    string, and (session-value NAME) gives it back, in this run and in the
    next ones; with a second argument, that is what comes back when NAME
    has no value. Setting nil forgets the name.

    A value can be anything `read' reads back: numbers, strings, symbols,
    and lists, vectors and maps of them. It is written as `prin1-to-string'
    writes it, when you set it, so a value with a part that has no written
    form -- a function, an atom, a thread -- is refused at once, with
    wrong-type-argument. Reading it back never evaluates it: a list comes
    back as a list, as if quoted.

    Values are never changed in place: to add to a list kept under a name,
    set the name again to the longer list. Names are shared by all the code
    that runs in the editor, so start each with the name of your module, as
    you would a variable's.

    The session is read after init.lisp, so a module that init.lisp loads
    finds the values of the last run only from the first command on. Read
    them when you need them, in the command that uses them, rather than
    when the module loads. A value set before the session is read is
    replaced by the one the last run left under the same name, if it left
    one.

    With several editors open, a value one of them sets reaches the others
    at their next write, unless they changed it themselves meanwhile: then
    each keeps its own until the last one written reaches the others. A
    name forgotten in one editor is still known to the others, and comes
    back from them.

EXAMPLES
    Keep a longer list of recent files:

        (setq recent-files-length 200)

    Keep nothing typed at a prompt from one run to the next:

        (setq save-history nil)

    Write the session every five minutes, or only when the editor quits:

        (setq session-save-interval 300)
        (setq session-save-interval nil)

    Open every file at its start:

        (setq save-place nil)

    The file opened last, from Lisp:

        (find-file (car (recent-files)))

    M-g r on a key of your own:

        (define-key nil "C-c f" 'find-recent-file)

    A function that remembers, from one run to the next, every directory
    it was given, once each, the newest first:

        (defun my-remember-directory (dir)
          (let ((known (session-value 'my-directories)))
            (unless (member dir known)
              (set-session-value 'my-directories (cons dir known)))))

    How many times a command has run, over every run:

        (set-session-value 'my-count (+ 1 (session-value 'my-count 0)))

LIMITS
    An editor that is killed, or that stops on an error inside the editor
    itself, does not write at that moment: the next start reads what was
    written last, a minute old at most unless `session-save-interval' says
    otherwise.

    With several editors open, what one forgets another still remembers,
    and writes back: `clear-recent-files' in one of two editors clears the
    list for good only when the other has quit, or done the same. What
    another editor added comes behind what this one knows, whichever was
    the more recent. And two editors writing in the same instant can each
    miss what the other is writing; the one still open puts it back at its
    next write.

    A place is a count of characters from the start of the file. A file
    changed by another program since it was left opens at the same count,
    which may no longer be the same line.

    Every value kept by name is written in the session file each time it
    is written, and read again each time: keep there what is worth keeping,
    not a buffer's text. A value whose line in the file was damaged no
    longer reads; `session-value' then gives the default, and the log says
    so.
