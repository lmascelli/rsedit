NAME
    themes - how faces are drawn, and choosing a theme

SYNOPSIS
    (theme-list)
    (theme-list-select)
    (theme-list-refresh)
    (select-theme NAME)
    (reset-theme)
    (available-themes)
    (set-face FACE &optional FOREGROUND BACKGROUND ATTRIBUTES)
    (define-face FACE &optional FOREGROUND BACKGROUND ATTRIBUTES)
    (face-style FACE)
    (reset-faces)
    (list-faces)
    (list-colors)
    current-theme
    theme-list-buffer-name
    theme-list-name-column
    theme-suffix

DESCRIPTION
    Everything the editor colours, it colours by name: a keyword is drawn
    in the face keyword, the region in the face region, the status line in
    mode-line. A face says how its text is drawn -- a colour for the text, a
    colour behind it, bold, italic, underline, reverse video -- and a theme
    says it for many faces at once.

    C-c t lists the themes, and Return on one applies it. To keep a choice,
    put it in init.lisp, after the line that loads the module,
    (eval-file "theme"):

        (select-theme 'gruvbox-dark)

    Twelve themes come with the editor: dracula, gruvbox-dark,
    gruvbox-light, monochrome, monokai, nord, soft-contrast-gray,
    solarized-dark, solarized-light, tango-dark, tomorrow-night and
    zenburn. monochrome sets no colour at all, only bold, italic, underline
    and reverse video, so it reads the same on any terminal.

THE LIST OF THEMES
    C-c t shows the themes installed, one to a line, with a * beside the one
    in force. Return applies the theme on the cursor's line, g reads the
    themes again, n and p move, q puts the list away. M-x reset-theme takes
    the theme away, and the faces look as the editor ships them.

THE FACES
        default              the text itself; no front end draws it yet
        region               the region, between point and the mark
        mode-line            the status line of the window you are in
        mode-line-inactive   the status line of the other windows
        window-separator     the line between windows side by side
        line-number          the line numbers, when they are on
        line-number-current  the number of the line point is on
        replace-match        the match M-% is asking about
        keyword  type  function  builtin  string  comment
                             the parts of a language its mode colours
        doc-comment  attribute  preprocessor
                             the same, named by rust-mode and cpp-mode
        error                the line saying a command failed, in its
                             output
        preview              what C-x r t is about to insert
        results-here         the entry M-g n is on, in its list
        results-target       the line that entry is about, in its file
        manpage-bold         bold, in a page of the system's manual
        manpage-underline    underlining, in one

    `list-faces' names every face there is. A face is made by being named,
    so a misspelt name is a new face that nothing draws -- and shows up
    there.

SETTING A FACE
        (set-face 'region "#f8f8f2" "#3a5fcd")
        (set-face 'comment "bright-black" nil '("italic"))

    FOREGROUND and BACKGROUND are colours, and nil or "" leaves that side
    to the terminal. ATTRIBUTES is a list of the attributes to turn on:
    "bold", "italic", "underline" and "reverse"; a name on its own, not in
    a list, is refused. `set-face' replaces the whole face, so what it is
    not given, the face loses. M-x set-face asks for the face and the two
    colours.

    A module that names a face of its own gives it its style with
    `define-face', which takes what `set-face' takes. That style is the
    face's as the editor ships it: `reset-faces' puts it back, and a theme
    that does not name the face leaves it.

    A colour is "#rrggbb", "#rgb", or one of sixteen names, which
    `list-colors' gives: black, red, green, yellow, blue, magenta, cyan and
    white, and each of them with bright- in front. It is drawn as asked on
    a terminal that says, in COLORTERM, that it shows any colour; on one
    that says 256color in TERM, as the nearest of its 256; on any other, as
    the nearest of its sixteen, which are the terminal's own. A name always
    lands on the colour of the same name.

    `face-style' says how a face is drawn now, as (FOREGROUND BACKGROUND
    ATTRIBUTE...): each colour written "#rrggbb", or nil, and the
    attributes after them rather than in a list of their own.

WRITING A THEME
    A theme is a file of Lisp in the editor's themes directory,
    (data-directory "themes"), that puts the list of its faces on a symbol:
    a file called night.lisp puts it on night-theme.

        (put 'night-theme 'faces
             '((keyword "#859900" nil ("bold"))
               (region  nil "#073642" nil)))

    Each entry is what `set-face' takes, so a theme is written the way a
    face is set. Loading the file changes nothing; `select-theme' applies
    it, after putting every face back with `reset-faces', so that nothing
    of the theme before is left. A face a theme does not name looks as it
    ships, the faces of the modules as `define-face' gave them. In the
    source tree the themes are in themes/, which the build copies.

LIMITS
    The terminal front end does not draw the face default: the text and the
    background keep the terminal's own colours, whatever the theme says.
    Set the terminal's colours to the ones in the theme's default entry.

EXAMPLES
    A theme from init.lisp:

        (select-theme 'nord)

    The region in a colour rather than in reverse video:

        (set-face 'region nil "bright-black")

    And back as the editor ships it:

        (set-face 'region nil nil '("reverse"))

    How keywords are drawn now:

        (face-style 'keyword)

    The themes there are to choose from:

        (available-themes)
