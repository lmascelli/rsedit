NAME
    writing-commands - when a setting is not enough

SYNOPSIS
    (defcommand NAME PARAMS SPECS &rest BODY)
    (string-prefix-p PREFIX S)
    (string-suffix-p SUFFIX S)

DESCRIPTION
    A command is a function the editor knows how to ask the arguments of.
    That is the whole of the difference: a function is called from Lisp,
    and a command can be run with M-x and put on a key as well.

        (defcommand insert-date () nil
          "Insert today's date."
          (insert (substring (shell-command-to-string "date +%Y-%m-%d")
                             0 -1)))

    After that M-x insert-date inserts the date at point, C-h f
    insert-date shows the string, and

        (define-key nil "C-c d" 'insert-date)

    puts it on a key. The `substring' takes off the newline date prints
    after the date. A definition like this goes in init.lisp, or in a module
    of your own that init.lisp loads with `require': the `configuration'
    page says where.

THE ARGUMENTS
    SPECS has a code for each parameter, and the editor collects the
    arguments before the command runs:

        "sPROMPT"   a string, as typed
        "nPROMPT"   a number
        "bPROMPT"   the name of a buffer, completed from those there are
        "fPROMPT"   the name of a file, completed from the disk
        "p"         the prefix argument as a count: 1 without one, 4
                    after C-u, 5 after C-u 5, -1 after C-u -
        "P"         the prefix argument as typed: nil without one, (4)
                    after C-u, 5 after C-u 5, the symbol - after C-u -
        "r"         the region, as two arguments: where it begins, and
                    where it ends

    Those with a PROMPT ask for their arguments in turn, each in a prompt
    that names the command; p, P and r ask nothing. An answer to "n" that
    is not a number is refused, and the prompt asks again. nil for SPECS is
    a command with no arguments.

        (defcommand surround (before after) ("sBefore: " "sAfter: ")
          "Put BEFORE and AFTER around the region."
          (let ((start (region-beginning)) (end (region-end)))
            (goto-char end) (insert after)
            (goto-char start) (insert before)))

    The codes are checked when the command is defined, not when it runs: a
    code the editor does not know, a prompt after p, P or r, or codes that
    give more or fewer values than there are parameters, r giving two, is
    an error then. A command that takes the region does not run when the
    mark is not set.

    From Lisp a command is a function like any other, and asks for
    nothing: (surround "<" ">") puts the two around the region. To ask, as
    M-x does, call it with `call-interactively'; `register-command' makes a
    command of a function defined with `defun'. The `keymaps' page has
    both.

WHAT A COMMAND WORKS WITH
    C-h a finds a function by a part of its name, and C-h f says what it
    does. The ones a command reaches for most, and the pages that have
    them:

        (point)  (goto-char POS)  (goto-line N)          editing
        (insert TEXT)  (delete-region FROM TO)           editing
        (buffer-string)  (buffer-substring FROM TO)      buffers
        (current-buffer)  (switch-to-buffer NAME)        buffers
        (region-beginning)  (region-end)  (mark)         killing
        (message FORMAT ARG...)  (log TEXT)              diagnostics

    And two of this page's own, for the names of buffers and files:
    `string-prefix-p' says whether a string begins with another, and
    `string-suffix-p' whether it ends with one.

        (string-suffix-p ".rs" (buffer-file-name))

    is t in a buffer visiting a Rust file, and nil in one visiting none.

ASKING SOMETHING ELSE
    A question that is not one of the arguments is asked with
    `minibuffer-read', or with `y-or-n' and `yes-or-no' for a yes or a no:
    the `minibuffer' and `files' pages have them. They return before the
    answer comes, and give it to a function of yours, because a prompt
    does not stop the editor: it goes on drawing while you type.

MARKING TEXT
    A command that has found something shows where with an overlay, a
    face on one span of text, and takes its marks away again by naming
    their category:

        (make-overlay START END 'error 10 'my-checker)
        (remove-overlays 'my-checker)

    Text shown and not in the buffer is virtual text. The `overlays' and
    `virtual-text' pages have both.

WORK THAT TAKES TIME
    A command runs while the editor waits for it, so a command that may
    take long hands its work to the background, with `background-call',
    and shows the result from a function called when the work is done. A
    program is run with `shell-command-start', which shows what it prints
    as it comes. The `background' and `shell' pages have them.

WHEN SOMETHING HAPPENS
        (add-hook nil "post-command-hook" 'my-function)
        (add-hook 'rust-mode "post-self-insert-hook" 'my-function)

    The first calls my-function after every command, in any mode; the
    second after every key that types itself, in Rust buffers. The `modes'
    page lists the hooks.

TRYING IT OUT
    M-: evaluates an expression and says what it returned, so a command
    can be tried before it has a key, as (surround "<" ">") is. What it
    defines is the editor's at once, as what init.lisp defines is, and a
    command defined again runs the new way the next time its key is
    pressed. So the way to work is: change the file of your own the
    command is in, load it again with M-: (eval-file "mine"), press the
    key. A defvar in the file leaves the value its variable has.

    C-h e shows the log, where a command that failed says why; with
    debug-on-error set, a failure opens its backtrace as well.

EXAMPLES
    How many characters the region holds:

        (defcommand count-region (start end) ("r")
          "Say how many characters the region holds."
          (message "%d characters" (- end start)))

    A command that uses the prefix argument, so that C-u 3 C-c i inserts
    three stars:

        (defcommand insert-stars (n) ("p")
          "Insert N stars."
          (dotimes (i n) (insert "*")))
        (define-key nil "C-c i" 'insert-stars)

    Ask for a buffer and say what mode it is in:

        (defcommand buffer-mode (name) ("bBuffer: ")
          "Say what major mode the buffer NAME is in."
          (message "%s is in %s" name (major-mode name)))

    Whether the current buffer is the output of a shell command:

        (string-prefix-p "*Shell Output*" (current-buffer))
