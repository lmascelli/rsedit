      - opening a new file in a new unsaved buffer
      - opening a directory if dired is loaded (this can be done by defining a global variable
        *open-directory-callback* that dired install when loaded)
      A missing path gives an empty buffer that remembers where it goes, not marked modified --

      open, as `mod.rs' and `mod.rs<2>', and re-opening a file returns to its buffer rather
      than re-reading over your edits.

      with a dangling buffer reference causing when closing it an unwrap call in the
      get_current_buffer function
      `close_buffer' repointed the focused window only. Every window showing the buffer is
      repointed now, at the most recently used buffer that still exists -- which needed a
      recency list, since the buffer table is a HashMap with no order at all. The panic is
      left in place: with the cause fixed, a stale current-buffer name means a broken
      invariant and should say so loudly rather than limp on.

* Macro todo 
- [X] Switch to buffer command and buffer-list major mode
      `C-x b' prompts and completes fuzzily over buffer names; `C-x C-b' opens a listing with
      a modified mark, the name, the mode and the file. Like dired it keeps no state beside
      the buffer -- each line carries a name, read back by column since a buffer name may
      contain spaces. RET switches, d kills (asking first if there are unsaved changes), g
      refreshes, q puts it away.
- [X] Rsedit lisp mode
      The vocabulary is asked for rather than listed: `all-macros' and `all-functions' report
      what this editor actually has, including anything defined in your own init.lisp. Only
      the special forms are written down, because they have no binding to enumerate.
      `risp-refresh-vocabulary' rebuilds after you define something. This is also what
      `lisp-indent-line' had been waiting for -- indent.lisp shipped it with no mode to attach
      to, and it is now attached.
- [X] Shell command spawn with output capture
      `M-!' runs a command on the worker thread, so the editor stays usable while a build
      runs, and output is appended as it is produced. The worker gets no Env, so completion is
      reported by writing `--- exited 0 ---' into the buffer it is already writing to. Each
      command gets its own buffer, since two sharing one would interleave their lines. The
      running count is what keeps the renderer waking up -- the same problem `colouring_pending'
      solves for syntax highlighting.
- [X] manpage-mode: add to the global variables a list of path where to search for manpages.
                    when compiled for linux the default manpages dirs should be part of the
                    list at the start. provide a function to open the word under the cursor
                    as manpage if available and an other one to open a minibuffer to prompt
                    the user what manpages to open. also should provide a capf function to
                    list all available manpages that can be used for the minibuffer
                    completion of the second function
      `manpage-path' is handed to `man' as MANPATH, so it controls what is found as well as
      what is listed. `K' opens the word under the cursor, `C-h m' prompts with completion,
      and `capf-manpage-names' is the completion source. New primitives: getenv, setenv,
      path-separator, shell-command-to-string, strip-overstrike, data-directory.
      NOTE: the overstrike is *stripped* rather than turned into faces. This editor faces text
      through its mode's syntax rules and has nothing that can face an arbitrary span -- no
      text properties, no overlays -- so the emphasis is recovered from structure instead (a
      heading is a word alone at the left margin). Bold mid-sentence would need an overlay
      mechanism, which is a feature of its own.
