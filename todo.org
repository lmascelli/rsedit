- [X] Switch to buffer command and buffer-list major mode
      `C-x b' prompts and completes fuzzily over buffer names; `C-x C-b' opens a listing with
      a modified mark, the name, the mode and the file. Like dired it keeps no state beside
      the buffer -- each line carries a name, read back by column since a buffer name may
      contain spaces. RET switches, d kills (asking first if there are unsaved changes), g
      refreshes, q puts it away.
- [X] Rsedit lisp mode
      The vocabulary is asked for rather than listed: `all-macros' and `all-functions' report
      what this editor actually has, including anything defined in your own init.lisp. Only
      the special forms are written down, because they have no binding to enumerate.
      `risp-refresh-vocabulary' rebuilds after you define something. This is also what
      `lisp-indent-line' had been waiting for -- indent.lisp shipped it with no mode to attach
      to, and it is now attached.
- [X] Shell command spawn with output capture
      `M-!' runs a command on the worker thread, so the editor stays usable while a build
      runs, and output is appended as it is produced. The worker gets no Env, so completion is
      reported by writing `--- exited 0 ---' into the buffer it is already writing to. Each
      command gets its own buffer, since two sharing one would interleave their lines. The
      running count is what keeps the renderer waking up -- the same problem `colouring_pending'
      solves for syntax highlighting.

- [X] Overlay mechanism
      A face on one particular span, which a syntax rule cannot express -- rules are patterns
      over the text, and "this match, here" is not a pattern. A third producer of Highlight
      beside the mode's colouring and the region, drawn between them.
      The hard part is that these are the first stored positions in the editor: everything
      else either recomputes every frame or is invalidated by the next edit, and the mark is
      *deactivated* by every edit precisely so it never needs adjusting. Overlays are adjusted
      at the two doors instead. Insert moves `start' when it is at or before it and `end' only
      when strictly before, which is the whole of "neither end grows": a highlighted match
      stays exactly the text that matched, however much is typed either side. Delete clamps
      both ends and removes anything left covering nothing.
      Kept sorted by start, which makes the adjustment a binary search and a walk of the tail;
      a `furthest_end' makes the common case -- editing past everything highlighted -- one
      comparison. That is the place this would grow an interval tree if it ever needs one.
      Lisp: make-overlay, delete-overlay, remove-overlays, overlays-at, overlay-face.
      Deliberately left out: property bags (before-string, invisible and overlay keymaps need
      renderer and input support that does not exist, so they would be stored and ignored),
      and undo integration (an overlay destroyed by a delete does not come back -- restoring
      it means the undo history carrying state owned by other modules).
      The mark could now be an overlay. It should not be: it is deactivated by every edit so
      that it never needs adjusting, and folding it in would trade a rule that cannot go wrong
      for one that can.
