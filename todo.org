#+title: rsedit

* Work in progress.


* Fixes todo
- [ ] Better handling from tui input (C-_ is seen has C-S-7)
- [ ] primitive for making enter also indent the next line (optinally bound to Enter)
- [ ] pressing tab with a region selected insert the same indent in the whole region
      but should instead indent it.
- [ ] line numbers should be a per buffer property
- [ ] the worker that checks if a file has been modified should have a timeout on
      the function that checks it so it cannot block the other tasks on the scheduler.
      Moreover, when the file is reverted the cursor goes back to the start of the file,
      instead it should stay in the position where it was saturating to the end of the file
      if the outer edits changed it.
- [ ] I've seen that the modules commands, debug, common-keymaps, indent and minibuffer
      are not indipendent. Modules that provide indipendent features should be able to
      be loaded indipendently. Maybe some of the common feature between those are to be
      embedded in the base editor.


* Macro todo
- [ ] Enhance mode system: major mode switch and minor modes
- [ ] Finding things across files occur (matches in this buffer, in a buffer, RET to jump)
      then project-wide grep. You already have the compilation-buffer navigation pattern
      (next-error/compilation-goto), so occur and grep can reuse that entire mechanism
      — they're the same "list of places, jump to one" shape. And a project grep over
      a large tree is the second obvious worker.
- [ ] rectangle commands
- [ ] Keyboard macros, registers and bookmarks
- [ ] narrow-to-region
- [ ] Module dependency system (with functions like provide and requires) with a cached module
      table so that the same dependency is not loaded twice. Following that a module that
      aggregate the main useful modules and the common keymaps must be added to provide a
      simpler way to initialize a tipical configuration.
- [ ] multiple cursors
- [ ] LSP integration: for the moment, just warning and compilation errors, completions
      and code actions must be supported. The server for a given language can be configued
      and the configuration stored in the major mode variables with a convenction that this
      module can follow. As usual the module is lisp but every sharable functionality and
      features that have performace need must be implemented in Rust.
- [ ] An eshell like mode, where it is possible to both read from stdin/stderr associated
      to a shell process. A mark to the end of the buffer is kept so that commands can be
      obtained when pressing enter and be send to stdin. It must have a configurable
      history where duplicates entries can be deleted. It also must support bash, Windows's
      cmd and powershell and be configurable for other shells. Detail on how to do that and
      their possible complications must be discussed. The spawned process must be handled in
      a separate thread and the handle returned to the lisp environment. Also lisp expression
      should be evalued, if this makes the module too complex maybe consider adding some special
      syntax that consent distinguish between a lisp expression and a shell command.
- [ ] Integrated terminal emulation
- [ ] Lisp bytecode interpreter
- [ ] A manual of the editor
