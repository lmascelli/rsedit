PROMPT PER I PROSSIMI PUNTI DI rsedit (dopo il progetto del modulo lsp)
=====================================================================

Come usarli
-----------
- Un punto per sessione, sessione nuova ogni volta: il contesto vecchio
  costa token a ogni turno e non serve.
- Incolla il PREAMBOLO, poi il prompt del punto, in un messaggio solo.
- Ogni prompt dice già quali file leggere e quali test lanciare per primi:
  così non si esplora il repository. Se un punto ne richiede altri, li si
  legge, ma solo la parte che serve (grep prima, Read con offset poi).
- La patch del progetto (doc/progetto-lsp.typ) deve essere già nel main;
  se non lo è, allegala e aggiungi: "Applica prima la patch allegata con
  git am."
- Ordine: N1, N5 -> M3a -> N8 -> N9 -> N10 -> M3b -> M3c -> N7 -> N6
  -> M3d -> N2+N3, N4 -> M3e.
  N1 e N5 si possono fare nella stessa sessione (sono piccoli e
  separati).
- I punti facoltativi (N7-N10, in fondo) non servono alla prima versione:
  si fanno quando serve, ciascuno dopo il punto indicato nel suo titolo.
- Da eseguire: N7


PREAMBOLO
---------
Lavora sul main attuale di lmascelli/rsedit. Non modificare GitHub: prepara
una patch per git am, allegata in chat, verificata su un checkout pulito con
cargo test --workspace. Segui doc/documentazione.typ (leggi solo §Le regole e
la lista di controllo) per manpage, manuale, docstring e test. Non eseguire
typst e non nominarlo nel commit. Leggi solo i file indicati, e di questi le
parti che servono: grep prima, poi Read con offset. Durante il lavoro lancia
solo i test del punto (cargo test -p rsedit_core NOME); la suite intera una
volta, alla fine, sul checkout pulito. Niente riepiloghi intermedi né
domande, salvo dove il prompt dice "prima proponi". Alla fine, in poche
righe: percorso della patch, scelte fatte, cosa non hai verificato. Il
nucleo resta agnostico: nessun riferimento a progetti o LSP fuori dai
moduli project e lsp. Il progetto è doc/progetto-lsp.typ: leggine solo le
sezioni citate.
