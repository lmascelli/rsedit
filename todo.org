[rsedit · modalità PATCH]

Modifica: <<cosa deve cambiare e comportamento atteso>>
Dove: <<file e simbolo, es. core/src/buffer.rs → fn delete_line>>
Nome patch: <<nome-breve>>
Verifica cargo: si test mirati

Regole (tutte obbligatorie). $REPO = radice del repo, $SCRATCH = la tua scratchpad directory.
1. NON toccare il checkout in $REPO: niente edit, commit, branch, push.
   Lavora in un worktree temporaneo:
   git -C $REPO worktree add -q --detach $SCRATCH/wt HEAD
2. Contesto minimo: leggi solo i file in "Dove", e solo le parti necessarie
   (Grep per trovare il simbolo, poi Read con offset/limit). Niente esplorazione
   del repo, niente subagenti, niente piano. Se manca un'informazione, fermati e chiedimela.
3. Modifiche con Edit, minime e nello stile del codice esistente. Nessun refactoring,
   commento o riformattazione non richiesti.
4. Se "Verifica cargo" è sì, nel worktree:
   CARGO_TARGET_DIR=$REPO/target cargo check -q 2>&1 | tail -n 30
   e correggi gli errori. E genera test mirati per il fix o la feature aggiunta.
5. Genera il patch, rimuovi il worktree e controlla che il patch si applichi:
   cd $SCRATCH/wt && git add -A && git diff --cached > $SCRATCH/<<nome-breve>>.patch
   git -C $REPO worktree remove --force $SCRATCH/wt
   git -C $REPO apply --check $SCRATCH/<<nome-breve>>.patch
6. Inviami il file con SendUserFile. NON riportare il diff in chat: rispondi solo
   con il percorso del patch e al massimo 3 righe su cosa cambia.
